# 글빨 · geulppal

Claude가 문서와 글을 쓸 때 과장, 반복, 번역투를 줄이는 스킬입니다. 사실·수치·조건과 작성자의 말투는 그대로 남깁니다. README, PR 본문, 기획서, 소개글, 이메일 같은 한국어 글을 중심으로 하며, 영어 글에도 쓸 수 있습니다.

README를 고칠 때마다 비슷한 수식어와 불필요한 설명을 다시 걷어내야 해서 만들었습니다.

## 벤치마크

Claude Code에서 같은 요청·모델·설정으로 글빨 유무를 비교했습니다. 스킬을 고정한 뒤 처음 보는 사례로 확인했고, 각 사례를 조건마다 2회 실행했습니다. 판정은 작성 모델과 다른 모델이 했습니다.

| 사실·조건·상태를 지킨 결과 | 글빨 없음 | 글빨 0.2 | 글빨 0.3 |
|---|---|---|---|
| 사람이 쓴 README 16개(2018~2022년 오픈소스) | 20/32 | 30/32 | 31/32 |
| 사람이 쓴 글 9개(2018~2022년 공개 글) | 8/18 | 16/18 | 16/18 |
| 모델이 만든 문서 12개 | 12/24 | 18/24 | (확인용으로 쓰지 않음) |

- 글빨 없이 다듬으면 원문에 없는 약속이나 경험을 넣는 경우가 많았습니다. 전해 들은 말("가능하다고 합니다")을 단정("가능합니다")으로 바꾸는 경우도 많았습니다.
- 0.3은 국내 글쓰기 자료와 사람이 쓴 글을 바탕으로 고친 버전입니다. 사람이 쓴 글에서 0.2보다 낫다는 근거는 얻지 못했습니다. 0.2에서 남았던 조건 넓히기 오류(`해외에 계셔서` → `해외 체류 등으로`)는 0.3에서 나오지 않았지만, 그 사례를 보고 고친 결과입니다.
- 0.3에도 추측을 단정으로 바꾸거나(`가장 어려울 텐데` → `가장 어려운 일은`) 범위를 좁히는(`온라인으로` → `온라인으로만`) 오류가 남아 있습니다.
- 판정 모델은 README에서 글빨 0.3 결과를 글빨 없는 결과보다 16 대 2로 더 자주 골랐습니다. 하지만 사람이 쓴 원문보다도 고친 글을 거의 항상 골라서, 더 잘 읽힌다고 단정하지는 않습니다.
- 글빨 0.3을 쓰면 실행당 비용이 글빨 없이 쓸 때의 약 2.2~2.5배였습니다(사람이 쓴 글과 README 기준).

작은 표본을 모델이 판정한 결과이며, 사람의 평가는 아닙니다. [방법·사례별 결과·한계](evals/results/README.md)

## 설치

**Claude Code**: 스킬 폴더를 복사합니다. 모든 프로젝트에서 쓰려면 개인 스킬 폴더에, 한 프로젝트에서만 쓰려면 그 프로젝트의 `.claude/skills/`에 둡니다.

```bash
git clone https://github.com/Guksu/geulppal.git
mkdir -p ~/.claude/skills
cp -r geulppal/skills/geulppal ~/.claude/skills/geulppal
```

같은 이름의 스킬이 이미 있다면 먼저 내용을 비교하세요.

**Claude 웹·데스크톱**: `skills/geulppal/` 폴더를 ZIP으로 묶어 업로드합니다. ZIP을 열었을 때 `geulppal/SKILL.md`가 있어야 합니다.

```bash
cd geulppal/skills && zip -r geulppal.zip geulppal
```

[Claude Code 스킬 위치](https://code.claude.com/docs/en/skills) · [ZIP 작성 안내](https://support.claude.com/en/articles/12512198-how-to-create-custom-skills)

설치되는 것은 `skills/geulppal/`의 파일 세 개(약 25KB)뿐입니다. 평가 자료와 스크립트는 들어가지 않습니다.
