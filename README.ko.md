# 글빨 · geulppal

Claude가 문서와 글을 새로 쓰거나 고칠 때 과장, 반복, 번역투를 줄이는 스킬입니다. 원문 없이 코드나 메모만 주고 써 달라고 해도 받은 자료에 있는 사실만 쓰고, 고칠 때는 사실·수치·조건과 작성자의 말투를 그대로 남깁니다. README, PR 본문, 기획서, 소개글, 이메일 같은 한국어 글을 중심으로 하며, 영어 글에도 쓸 수 있습니다.

Claude에게 README나 보고서를 써 달라고 할 때마다 비슷한 수식어와 불필요한 설명을 다시 걷어내야 해서 만들었습니다.

## 벤치마크

Claude Code에서 같은 요청·모델·설정으로 글빨 유무를 비교했습니다. 스킬을 고정한 뒤 처음 보는 사례로 확인했고, 각 사례를 조건마다 2회 실행했습니다. 판정은 작성 모델과 다른 모델이 했습니다.

**새로 쓰기**: 2022년 이전 공개 저장소의 코드만 주고(README는 뺌) "이 패키지 README를 한국어로 써 줘"라고 요청했습니다. 판정 모델이 같은 코드를 읽고, 결과에 쓴 명령·함수·수치·링크마다 근거가 있는지 확인했습니다.

| README 초안 | 글빨 없음 | 글빨 0.3 | 글빨 0.4.0 | 글빨 0.4.1 |
|---|---|---|---|---|
| 근거를 확인할 수 있는 내용만 쓴 결과: 확인용 4개 | 3/8 | 6/8 | 7/8 | (실행 안 함) |
| 같은 결과: 0.4.0 고정 뒤 추가한 5개 | 9/10 | 9/10 | 6/10 | 10/10 (이 사례를 보고 고침) |
| 같은 결과: 0.4.1을 고치기 전에 추가한 4개 | 2/8 | (실행 안 함) | 8/8 | 8/8 |
| 판정 모델 품질 비교 (0.4.0과) | 0 대 5 | 1 대 5 | | 2 대 7 |
| 사람 블라인드 비교 (0.4.0과) | 0 대 3 (비슷함 3) | 1 대 1 (비슷함 2) | | (하지 않음) |

- 글빨 없이 쓴 README는 코드와 반대로 동작을 설명하거나(점수가 낮은 후보부터 돌려주는 함수를 "높은 순서"로) 코드에 없는 외부 링크와 지원 환경을 넣는 경우가 많았습니다.
- 0.3은 정확했지만 소개한 기능의 사용 예나 패키지가 필요한 이유를 빼는 경우가 있었습니다. 0.4는 새로 쓰는 글을 위한 지침을 더했습니다. 저장소 소유자가 직접 고른 블라인드 비교에서는 0.4.0 결과를 같은 커밋의 사람 README보다 8 대 0으로 골랐습니다.
- 0.4.0은 코드에 없는 의존성 문서 링크(`date-fns.org`)를 넣는 경우가 있었습니다. 0.4.1은 자료에 적힌 주소만 링크로 씁니다. 다만 0.4.1을 고친 뒤 만든 사례에서는 0.4.0도 링크를 넣지 않아 차이를 확인하지 못했고, 판정 모델의 품질 비교에서는 0.4.0이 근소하게 앞섰습니다.

메모만 주고 보도자료·안내문·보고서·기획서를 써 달라고 했을 때(2018~2022년 정책브리핑 기사에서 뽑은 메모 13개)는 차이가 더 컸습니다.

| 메모로 쓴 업무 글 | 글빨 없음 | 글빨 0.4.1 |
|---|---|---|
| 메모에 근거가 있는 내용만 쓴 결과: 개발용·확인용 8개 | 5/16 | 15/16 |
| 같은 결과: 처음 보는 5개 | 4/10 | 9/10 |
| 판정 모델 품질 비교 | 0 대 6 | |
| 사람 블라인드 비교 | 1 대 3 (비슷함 1) | |

- 글빨 없이 쓴 글은 메모의 계획(`권고·지도할 계획`)을 시행한 일처럼 쓰거나, 메모에 없는 기대 효과를 붙이는 경우가 많았습니다.
- 보도자료를 원래 사람 기사와 블라인드로 비교했을 때는 사람 기사를 2 대 1로 더 골랐습니다. 판정 모델은 반대로 글빨 쪽을 골랐습니다.

블로그 글·에세이를 글쓴이 메모나 한두 줄 설명만 주고 써 달라고 했을 때(2019~2022년 정책기자단 체험기 16편)는 지어낸 경험이 가장 큰 문제였습니다.

| 블로그 글·에세이 | 글빨 없음 | 글빨 0.4.1 | 글빨 0.4.3 |
|---|---|---|---|
| 입력에 있는 경험만 쓴 결과: 처음 보는 12개 | 6/24 | 10/16 | 22/24 |
| 같은 결과: 한두 줄만 준 사례 | 0/8 | 0/6 | 8/8 |
| 판정 모델 품질 비교(0.4.3과) | 4 대 0 | 3 대 1 | |
| 사람 블라인드 비교(0.4.3과) | 2 대 2 | 0 대 0 (비슷함 4) | |

- 글빨 없이 쓴 글은 메모에 없는 장면("볼펜으로 꾹꾹 눌러 적었다"), 속마음, 깨달음을 결과 하나에 평균 2.6~5.8개 넣었습니다. 0.4.3은 0.1개였습니다.
- 한두 줄만 주면 0.4.3은 그 내용으로 짧게 쓰고 글을 늘릴 경험을 물어봅니다. 지어내지는 않지만 블로그 한 편을 기대했다면 짧습니다.
- 판정 모델은 품질에서 0.4.3을 덜 골랐습니다. 짧은 경험담을 소제목과 목록으로 잘게 나눴다는 이유가 많았습니다.
- 원래 사람 글과 블라인드로 비교했을 때는 사람 글을 5 대 0(비슷함 1)으로 골랐습니다. 지어내지 않게는 됐지만 사람이 쓴 체험기만큼 읽히지는 않습니다.

짧은 소설을 한두 줄 설명이나 설정 메모(일부는 저작권이 끝난 근대 단편을 문체 참고로 붙임)만 주고 써 달라고 했을 때는, 요청한 조건을 지킨 정도가 비슷했고 판정 모델은 글빨 쪽 글을 골랐습니다.

| 짧은 소설 | 글빨 없음 | 글빨 0.4.3 |
|---|---|---|
| 요청한 조건·설정을 지킨 결과: 처음 보는 8개 | 12/16 | 10/16 |
| 요청한 분량 안에 든 결과(분량을 요청한 6개) | 3/12 | 5/12 |
| 판정 모델 품질 비교 | 0 대 10 | |

- 0.4.3은 감정을 설명하지 않고 행동과 사물로 보여 주고, 결말을 교훈으로 닫지 않는다는 이유로 골랐습니다. 사람 블라인드 비교는 아직 하지 않았습니다.
- 분량을 정하지 않은 한두 줄 입력에서 0.4.3은 글빨 없이 쓸 때보다 짧게 썼습니다(사례 6개 평균 공백 빼고 962자, 글빨 없음은 1,618자).
- 두 조건 모두 사투리 요청을 빠뜨리거나 문체 참고 글의 문장을 거의 그대로 옮긴 경우가 있었습니다.

**고치기**: 사람이 쓴 글과 모델이 쓴 글을 주고 다듬어 달라고 했습니다.

| 사실·조건·상태를 지킨 결과 | 글빨 없음 | 글빨 0.2 | 글빨 0.3 | 글빨 0.4 |
|---|---|---|---|---|
| 사람이 쓴 README 16개(2018~2022년 오픈소스) | 20/32 | 30/32 | 31/32 | 31/32 (0.4.0) |
| 사람이 쓴 글 9개(2018~2022년 공개 글) | 8/18 | 16/18 | 16/18 | (실행 안 함) |
| 모델이 만든 문서 12개 | 12/24 | 18/24 | (확인용으로 쓰지 않음) | (실행 안 함) |

- 글빨 없이 다듬으면 원문에 없는 약속이나 경험을 넣는 경우가 많았습니다. 전해 들은 말("가능하다고 합니다")을 단정("가능합니다")으로 바꾸는 경우도 많았습니다.
- 0.3에도 추측을 단정으로 바꾸거나(`가장 어려울 텐데` → `가장 어려운 일은`) 범위를 좁히는(`온라인으로` → `온라인으로만`) 오류가 남아 있습니다. 0.4는 고치는 지침을 바꾸지 않았습니다.
- 판정 모델은 사람이 쓴 원문보다 고친 글을 거의 항상 골랐습니다. 저장소 소유자가 직접 고른 블라인드 비교에서는 고친 글 22쌍 중 16쌍을 "비슷하다"고 봤습니다. 고치기에서는 글빨의 효과가 정확성에 있고, 읽기 좋아졌다고 단정하지는 않습니다.
- 글빨을 쓰면 실행당 비용이 README 초안에서는 글빨 없이 쓸 때의 약 1.5~1.7배, 메모로 쓴 업무 글과 블로그 글에서는 약 2배, 짧은 소설에서는 약 1.5배, 고치기에서는 약 2.2~2.5배였습니다.

작은 표본이고, 블라인드 비교의 평가자는 한 명입니다. [방법·사례별 결과·한계](evals/results/README.md)

## 설치

**Claude Code**: 스킬 폴더를 복사합니다. 모든 프로젝트에서 쓰려면 개인 스킬 폴더에, 한 프로젝트에서만 쓰려면 그 프로젝트의 `.claude/skills/`에 둡니다.

```bash
git clone https://github.com/Guksu/geulppal.git
mkdir -p ~/.claude/skills
cp -r geulppal/skills/geulppal ~/.claude/skills/geulppal
```

같은 이름의 스킬이 이미 있다면 먼저 내용을 비교하세요.

**Claude 웹·데스크톱**: `skills/geulppal/` 폴더를 ZIP으로 묶어 업로드합니다. ZIP을 열었을 때 `geulppal/SKILL.md`가 있어야 합니다.

```bash
cd geulppal/skills && zip -r geulppal.zip geulppal
```

[Claude Code 스킬 위치](https://code.claude.com/docs/en/skills) · [ZIP 작성 안내](https://support.claude.com/en/articles/12512198-how-to-create-custom-skills)

설치되는 것은 `skills/geulppal/`의 파일 세 개(약 25KB)뿐입니다. 평가 자료와 스크립트는 들어가지 않습니다.
