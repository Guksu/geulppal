# 글빨 · geulppal

Claude가 쓴 한국어를 사람들이 평소에 쓰는 한국어로 다듬는 스킬입니다. `조용한 실패`(silent failure)처럼 영어 표현을 낱말대로 옮긴 말, 작업 중에 붙인 이름을 설명 없이 쓴 문장, 명사만 늘어놓거나 화살표로 대신한 설명, 번역투와 과장을 고칩니다. 고치면서 사실·수치·조건과 작성자의 말투는 그대로 둡니다. Claude의 답변과 작업 보고, README·PR·커밋 설명 같은 한국어 글이 중심이고, 영어 글의 과장과 반복을 줄일 때도 쓸 수 있습니다.

Claude가 한국어로 답할 때마다 영어를 옮긴 듯한 말과 어색한 문장을 다시 고쳐 읽어야 해서 만들었습니다.

[English](README.md) · [설치](#설치) · [벤치마크](evals/results/README.md) · [평가 보고서 1차](evals/results/REPORT.md) · [2차](evals/results/REPORT-human.md) · [3차](evals/results/REPORT-readme.md) · [4차](evals/results/REPORT-draft-readme.md) · [5차](evals/results/REPORT-draft-memo.md) · [6차](evals/results/REPORT-draft-blog.md) · [7차](evals/results/REPORT-draft-fiction.md)

> **원문** 설정 파일이 없으면 이 함수는 조용히 실패합니다. 환경 변수가 진실의 원천이고, 테스트는 행복한 경로만 다룹니다.
>
> **수정안** 설정 파일이 없으면 이 함수는 오류를 내지 않고 넘어갑니다. 기준이 되는 값은 환경 변수에 있고, 테스트는 문제가 없을 때의 흐름만 다룹니다.

동작을 보여 주려고 만든 예시이며 평가 결과가 아닙니다. 독자가 평소에 쓰는 용어(캐시, 렌더링, 롤백)는 억지로 바꾸지 않습니다. `검토 중`을 `완료`로 바꾸거나, 구체적으로 보이게 하려고 사실을 지어내지 않습니다. 이미 자연스럽고 정확한 문장은 그대로 둡니다. AI 작성 여부를 판별하거나 탐지기 통과율을 보장하는 기능은 없습니다.

## 지금까지의 평가

0.4까지의 평가는 글빨이 글을 다듬거나 새로 쓸 때 뜻을 바꾸지 않는지, 자료에 없는 내용을 지어내지 않는지를 쟀습니다. 0.5.0에서 중심을 옮긴 한국어 표현(낱말대로 옮긴 말, 낯선 이름, 어색한 문장 구조)은 아직 재지 않았습니다. 그동안 평가에서 나온 한국어 결과 1,318개에는 `조용한 실패` 같은 표현이 한 번도 나오지 않았습니다. 실제 Claude 답변을 모아 이 부분을 재는 평가를 따로 만들 예정입니다.

| 무엇을 쟀나 | 글빨 없음 | 글빨 |
|---|---|---|
| 사람이 쓴 README 16개를 다듬을 때 사실·조건을 지킨 결과 | 20/32 | 31/32 (0.3) |
| 사람이 쓴 글 9개를 다듬을 때 같은 기준 | 8/18 | 16/18 (0.3) |
| 코드만 보고 README를 쓸 때 근거 있는 내용만 쓴 결과 (처음 보는 4개) | 2/8 | 8/8 (0.4.1) |
| 메모로 업무 글을 쓸 때 메모에 있는 내용만 쓴 결과 (처음 보는 5개) | 4/10 | 9/10 (0.4.1) |
| 블로그 글을 쓸 때 입력에 있는 경험만 쓴 결과 (처음 보는 12개) | 6/24 | 22/24 (0.4.3) |
| 짧은 소설에서 요청한 조건을 지킨 결과 (처음 보는 8개) | 12/16 | 10/16 (0.4.3) |

- 글빨 없이 다듬으면 전해 들은 말("가능하다고 합니다")을 단정("가능합니다")으로 바꾸거나, 원문에 없는 약속과 경험을 넣는 경우가 많았습니다.
- 저장소 소유자가 직접 고른 블라인드 비교에서는 다듬은 글 22쌍 중 16쌍을 "비슷하다"고 봤습니다. 정확성은 나아졌지만, 읽기 좋아졌다고 말할 근거는 아직 없습니다.
- 새로 쓸 때의 내용 규칙(코드 읽기, 링크, 메모의 수치, 자기 경험)은 0.5.0부터 [문서별 판단](skills/geulppal/references/document-types.md)으로 옮겼습니다. 위 결과는 이 규칙이 본문에 있던 버전에서 잰 것이고, 옮긴 뒤에는 다시 재지 않았습니다.
- 글빨을 쓰면 실행당 비용이 글빨 없이 쓸 때의 약 1.5~2.5배였습니다.

작은 표본이고, 블라인드 비교의 평가자는 한 명입니다. [방법·사례별 결과·한계](evals/results/README.md)

## 설치

**Claude Code**: 스킬 폴더를 복사합니다. 모든 프로젝트에서 쓰려면 개인 스킬 폴더에, 한 프로젝트에서만 쓰려면 그 프로젝트의 `.claude/skills/`에 둡니다.

```bash
git clone https://github.com/Guksu/geulppal.git
mkdir -p ~/.claude/skills
cp -r geulppal/skills/geulppal ~/.claude/skills/geulppal
```

같은 이름의 스킬이 이미 있다면 먼저 내용을 비교하세요.

**Claude 웹·데스크톱**: `skills/geulppal/` 폴더를 ZIP으로 묶어 업로드합니다. ZIP을 열었을 때 `geulppal/SKILL.md`가 있어야 합니다.

```bash
cd geulppal/skills && zip -r geulppal.zip geulppal
```

[Claude Code 스킬 위치](https://code.claude.com/docs/en/skills) · [ZIP 작성 안내](https://support.claude.com/en/articles/12512198-how-to-create-custom-skills)

설치되는 것은 `skills/geulppal/`의 파일 세 개(약 34KB)뿐입니다. 평가 자료와 스크립트는 들어가지 않습니다.

## 첫 요청

설치한 뒤 Claude에 이렇게 요청해 보세요.

> /geulppal 방금 한 작업을 한국어로 정리해 줘.

> /geulppal 이 PR 설명에서 영어를 그대로 옮긴 말과 어색한 문장을 고쳐 줘.

> /geulppal 이 저장소의 README를 한국어로 써 줘.

붙여 넣을 글을 요청하면 완성문만 돌려줍니다. 자료에 없어 비워 둔 사실(배포 여부, 단위가 빠진 수치 등)처럼 확인할 것이 있을 때만 짧게 알립니다.

`/geulppal` 없이 "자연스럽게 다듬어줘", "번역투 고쳐줘", "AI 티 빼줘"처럼 요청해도 Claude가 스킬을 고를 수 있습니다. 0.2.1 설명으로 잰 자동 선택 결과는 다음과 같습니다. 이 요청들을 본 뒤 설명을 고쳤기 때문에 독립 평가 결과가 아니고, 설명을 바꾼 0.5.0에서는 다시 재지 않았습니다. [자동 선택 결과](evals/results/2026-10-27-trigger/trigger-v0.2.1.md)

| 요청 | 스킬을 고른 실행 |
|---|---|
| 글쓰기 요청 | 24회 중 23회 |
| 코드·조회·AI 작성 판별 요청 | 20회 중 0회 |

## 구성

- [SKILL.md](skills/geulppal/SKILL.md): 한국어 독자가 멈칫하는 곳(낱말대로 옮긴 말, 낯선 이름, 문장 구조, 번역투), 과장·반복, 뜻 지키기, 출력 방식
- [문서별 판단](skills/geulppal/references/document-types.md): 원문 없이 새로 쓸 때의 내용 규칙, README·PR·기획서·블로그·이메일 기준
- [문장 예시](skills/geulppal/references/editing-examples.md): 고칠 문장과 그대로 둘 문장
- [조사 기록](research/findings.md): 기존 README 수정, 공개 스킬과 글쓰기 자료에서 채택한 기준
- [국내 자료 조사](research/korean-sources.md): 국립국어원 『새국어생활』 번역투 특집 등에서 정리한 기준과 사람이 쓴 평가 자료
- [평가 방법](evals/README.md): 평가 사례, 판정 기준, 실행 스크립트와 다시 돌리는 방법
