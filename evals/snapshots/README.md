# 스킬 스냅샷

평가에 쓴 스킬 버전을 그대로 보관한다. 실행 기록(`results/<실행>/records.json`)의 `manifest/<조건>` 항목에 어떤 스냅샷을 썼는지와 해시가 남는다. 해시는 폴더 안 파일의 상대 경로와 내용으로 만든 SHA-256이다(`scripts/eval/lib/common.mjs`의 `treeHash`). 값은 [`hashes.json`](hashes.json)에 있다.

| 버전 | 조건 이름 | 내용 |
|---|---|---|
| `v0.1.0` | B0 | 초기 스킬(커밋 `00f2393`) |
| `v0.2.0-r1` | B1 | 1라운드 후보. 본문과 사용자에게 하는 말 구분, 결론을 근거 범위로 좁히기, 새 도입의 반복 점검, 측정 예시 교체 |
| `v0.2.0-r2` | B2 | 2라운드 후보이자 최종 후보. 메모 허용 범위를 좁히고, 결과만 요청하면 메모를 붙이지 않으며, 원문 안의 귀속(의견·결정)을 남긴다 |
| `v0.2.1` | B(사람 글 평가), 자동 선택 | `description`에 영어 작업 키워드를 더한 버전. 본문과 참조 문서는 `v0.2.0-r2`와 같다 |
| `v0.3.0-r1` | C1 | 사람 글 평가 1라운드 후보. 전해 들은 말·추측 보존, 범위어(`만`·`등`) 추가·삭제 금지, 번역투 판단표, 합친 문장의 사실 누락 점검, 진단만 요청하면 대체 문구 없음, 후기 글의 덧붙은 소제목 되돌리기, 공공 안내문 기준 |
| `v0.3.0-r2` | C2, C | 2라운드 후보이자 0.3.0. r1에서 소제목 규칙을 빼고, 다듬기 요청에서 호응·반복·꼬인 수식을 고치되 어감을 지키게 하고, 이메일·안내문도 문서별 판단을 읽게 했다. `skills/geulppal`과 같다 |
| `v0.3.1-r1` | D1, D | 남은 오류 줄이기 후보. 완성 점검에 전해 들은 말·추측·의견·정도·범위 표시를 원문과 같은 강도와 시제로 대조하는 항목을 넣었다. 확인용 사례에서 0.3.0과 차이가 없어 채택하지 않았다 |

`node scripts/eval/check.mjs`는 각 폴더의 해시가 `hashes.json`과 같은지 확인한다.
