# 문장 예시

아래 예시는 편집 판단을 설명하기 위해 만든 가상 문장이다. 실제 제품의 기능·성과에 대한 근거로 사용하지 않는다. 수정안은 유일한 정답이 아니다.

## 한국어

### 기능을 평가하지 말고 설명하기

원문: “노트함은 단순한 메모 도구를 넘어 업무 생산성을 혁신하는 강력한 솔루션입니다. 메모에 태그를 붙이고 태그로 검색할 수 있습니다.”

수정: “노트함은 메모에 태그를 붙이고 태그로 검색하는 도구입니다.”

제공된 기능으로 설명했다. 저장 방식·검색 속도·동기화 기능을 새로 넣지 않았다.

### 명사 뒤에 약한 동사가 이어질 때

원문: “담당자는 제출된 파일에 대한 검토를 진행한 후 승인 여부에 대한 안내를 수행합니다.”

수정: “담당자는 제출된 파일을 검토한 뒤 승인 여부를 안내합니다.”

누가 하는지는 그대로 두고 행위를 직접 썼다. `검토`, `안내`라는 명사가 모든 곳에서 나쁜 것은 아니다. 항목 제목인 “제출 파일 검토”는 그대로 쓸 수 있다.

### 사실을 모르면 더 구체적으로 꾸미지 않기

원문: “이번 변경으로 처리 성능이 크게 향상됐습니다.”

수정 가능 범위: “이번 변경으로 처리 성능이 향상됐습니다.”

`크게`를 덜어도 성능 향상이라는 주장은 남는다. 단순 윤문이면 원문 주장으로 다루며 새 측정치를 넣지 않는다. 근거를 요구하는 보고서라면 어떤 성능을 어떻게 측정했는지 확인해야 한다. `응답 시간이 40% 줄었다`나 `캐시를 도입했다`를 만들어 채우지 않는다.

### 결론을 근거의 범위로 좁히고 측정 조건과 비용 남기기

원문: “새 이미지 캐시로 앱이 훨씬 빨라졌습니다. 안드로이드 기기 3대에서 각 20회 측정한 결과, 목록 화면의 첫 로딩 시간 중앙값이 2.4초에서 1.1초로 줄었습니다. 앱 용량은 3MB 늘었습니다. 다른 화면은 측정하지 않았습니다.”

수정: “새 이미지 캐시를 적용한 뒤 목록 화면의 첫 로딩이 빨라졌습니다. 안드로이드 기기 3대에서 각 20회 측정한 결과, 첫 로딩 시간 중앙값이 2.4초에서 1.1초로 줄었습니다. 앱 용량은 3MB 늘었고, 다른 화면은 측정하지 않았습니다.”

“앱이 훨씬 빨라졌다”는 측정한 화면보다 넓은 결론이다. 결론을 지우지 않고 측정한 화면으로 좁혔다. 기기 수·측정 횟수·지표·늘어난 용량·측정하지 않은 범위를 남겼다. “앱 전반의 체감 성능 향상”처럼 측정하지 않은 화면까지 넓히지 않는다.

### 실제로 필요한 부정과 대조는 보존하기

원문: “파일은 서버에 업로드되지 않고 기기에 저장됩니다. 기기를 바꾸면 기록이 자동으로 옮겨지지 않습니다.”

수정: 그대로 유지할 수 있다.

저장 위치와 기기 변경 시 동작을 설명한다. 부정문이 있다는 이유로 첫 문장을 “파일을 안전하게 저장합니다”로 바꾸면 정보가 사라진다.

### 약속과 계획을 약화하거나 강화하지 않기

원문: “다음 달부터 CSV 내보내기를 지원할 예정입니다. 팀 공유 기능은 도입을 검토하고 있습니다.”

수정: 그대로 유지할 수 있다.

둘 다 “지원합니다”로 쓰면 상태가 바뀐다. 둘 다 “검토 중입니다”로 써도 원래 약속을 바꾼다.

### 저자가 알려준 동기를 살리기

원문: “문서를 고칠 때마다 같은 수식어가 반복되는 것이 불편해서 이 도구를 만들었습니다. 사용하면서 부족한 부분을 계속 수정할 예정입니다.”

수정: “문서를 고칠 때마다 같은 수식어가 반복되는 게 불편해서 이 도구를 만들었습니다. 사용하면서 부족한 부분을 계속 수정할 예정입니다.”

해당 격식에 맞으면 이 정도로 충분하다. “수년간 수백 개의 문서를 고쳐 왔다” 같은 경력을 보태지 않는다. 작성자가 밝힌 업데이트 계획도 남긴다.

### 전해 들은 말과 추측을 남기기

원문: “구청 민원실에서도 신청서를 받는다고 합니다. 줄이 짧았던 건 평일 오전이라서였던 것 같습니다.”

수정: 그대로 유지할 수 있다.

`받는다고 합니다`는 작성자가 직접 확인하지 않았다는 표시이고, `~것 같습니다`는 추측이다. “구청 민원실에서도 신청서를 받습니다”, “평일 오전이라 줄이 짧았습니다”로 쓰면 확인한 사실처럼 바뀐다.

### 번역투는 같은 뜻으로 바꿀 수 있을 때만 고치기

원문: “이 도구는 여러 장점을 가지고 있습니다. 설정에 있어서의 핵심은 사용자로부터의 입력을 줄이는 것입니다.”

수정: “이 도구에는 여러 장점이 있습니다. 설정의 핵심은 사용자가 입력할 내용을 줄이는 것입니다.”

`가지고 있다`, `~에 있어서의`, `~로부터의`를 풀었다. 뜻은 그대로다. 법령 문구나 인용문 안의 같은 표현은 고치지 않는다.

### 영어 표현을 낱말대로 옮긴 말 풀기

원문: “설정 파일이 없으면 이 함수는 조용히 실패합니다. 환경 변수가 진실의 원천이고, 테스트는 행복한 경로만 다룹니다.”

수정: “설정 파일이 없으면 이 함수는 오류를 내지 않고 넘어갑니다. 기준이 되는 값은 환경 변수에 있고, 테스트는 문제가 없을 때의 흐름만 다룹니다.”

`조용히 실패`, `진실의 원천`, `행복한 경로`는 영어 표현을 아는 사람만 뜻을 짐작한다. 각각 가리키는 동작과 상태로 풀었다. 오류를 기록만 하는지, 아무것도 남기지 않는지는 코드에 따라 다르므로 확인하지 못했다면 `오류를 내지 않는다`까지만 쓴다.

### 작업 중에 붙인 이름 풀기

원문: “스냅샷 게이트에서 드리프트가 잡혀서 롤백했습니다.”

수정: “저장해 둔 결과와 새 결과를 비교하는 검사에서 값이 달라진 것이 확인돼 롤백했습니다.”

`스냅샷 게이트`는 작업하면서 붙인 이름이고 `드리프트`는 영어 은어다. 독자가 모르는 이름은 무엇을 하는 것인지로 풀어 쓴다. `롤백`처럼 독자가 아는 말은 그대로 둔다.

### 기호와 명사 나열로 쓴 설명을 문장으로

원문: “원인: 캐시 키 충돌 → 타 사용자 데이터 노출 가능성. 조치 완료: 키에 사용자 ID 포함.”

수정: “캐시 키가 겹쳐서 다른 사용자의 데이터가 보일 수 있었습니다. 키에 사용자 ID를 넣어 고쳤습니다.”

사용자에게 하는 설명이라 서술어가 있는 문장으로 썼다. `가능성`은 `보일 수 있었다`로 옮겨 실제로 노출됐다고 단정하지 않았다. 원문에 `조치 완료`가 없었다면 이미 고쳤는지 알 수 없으므로 `고쳤습니다`로 쓰지 않는다. 체크리스트나 표처럼 원래 개조식으로 쓰는 자리에서는 그대로 둘 수 있다.

### 짧은 요청에도 필요한 예의 남기기

원문: “안녕하세요, 수정한 제안서를 첨부합니다. 금요일까지 검토 의견을 보내 주시면 다음 버전에 반영하겠습니다. 감사합니다.”

수정: 그대로 유지할 수 있다.

인사와 감사는 받는 사람과의 관계에 쓰인다. 문서 밖 대화용 안내와 구분한다.

### 문체를 맞추려고 어미를 섞지 않기

원문: “필터를 선택할 수 있습니다. 선택된 필터를 통해 결과를 확인할 수 있습니다. 필터는 초기화가 가능합니다.”

수정: “필터를 선택하면 조건에 맞는 결과를 확인할 수 있습니다. 필터는 초기화할 수 있습니다.”

실제 동작이 원문과 일치하는 범위에서 묶는다. `확인해요`, `초기화하면 된다`를 섞어 리듬을 만들지 않는다.

### 인용과 설명을 구분하기

원문: “작성자는 ‘이 변화는 혁명적입니다’라고 말했습니다. 정말 획기적인 변화입니다.”

수정: “작성자는 ‘이 변화는 혁명적입니다’라고 말했습니다.”

인용 밖의 중복 평가를 덜었다. 인용문 안의 `혁명적`은 작성자 발언이므로 임의로 고치지 않았다.

## 영어

### 같은 기능을 평이하게 설명하기

Before: “NoteBox empowers users to seamlessly leverage tags to unlock effortless note discovery.”

After: “NoteBox lets users find notes by tag.”

태그로 찾는다는 내용만 있다면 이 정도면 된다. 원문에 다른 기능이 있다면 함께 보존한다.

### 정확한 전문용어는 유지하기

Before: “The fund uses leverage, which can increase both gains and losses.”

After: 문맥상 그대로 유지한다.

금융 용어인 leverage를 문체상의 상투어로 처리하지 않는다.

### 알려진 한계를 유지하기

Before: “The cache may reduce repeat requests. We have not measured its effect on memory use.”

After: 문맥상 그대로 유지한다.

`may`와 측정하지 않은 항목은 결과를 이해하는 데 필요한 내용이다. “The cache improves performance”로 합치면 주장 범위가 달라진다.

### 비교·목록·반복의 실제 용도 살리기

“The export includes three files: orders.csv, refunds.csv, and totals.csv.”는 실제 파일 목록이므로 세 항목을 유지한다. “Read access does not include delete permission.”도 권한의 차이를 설명하므로 부정 표현을 유지한다.
