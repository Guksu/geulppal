# 짧은 소설 평가

소설은 지어낸 이야기라서 "입력에 없는 내용을 쓰지 않았는가"로 평가할 수 없고, 비교할 정답 원문도 없다. 여기서는 요청한 조건과 설정을 지켰는지, 분량이 요청 범위 안인지를 확인한 뒤, 품질은 짝 비교와 사람 블라인드 비교로 본다. 블로그 평가에서 넣은 "입력에 없는 장면을 쓰지 않는다" 규칙(0.4.3)이 소설까지 메마르게 하지 않는지도 확인한다.

## 입력 세 가지

| 입력 | 사례 수 | 내용 |
|---|---|---|
| 한두 줄 설명 | 7 | 소재나 상황 한두 줄. 일부는 형식 조건(대사 없이, 현재형, 편지, 두 시점)을 함께 준다 |
| 설정 메모 | 5 | 인물 이름·나이·관계, 배경, 사건 순서, 시점, 결말 조건, 분량 |
| 문체 참고 글 + 설정 메모 | 5 | 저작권이 끝난 근대 단편의 앞부분을 말투 참고로 붙이고, 그 아래 설정 메모를 준다 |

사례는 실행 전에 [`spec.json`](spec.json)에 직접 썼다. 문체 참고 글은 위키문헌의 김유정 「동백꽃」(1936)과 현진건 「운수 좋은 날」(1924) 앞부분이다. 두 작가는 각각 1937년, 1943년에 세상을 떠나 저작권 보호기간이 끝났다.

## 판정

- **조건 판정**([`draft-fiction-check.md`](../judge/draft-fiction-check.md)): 시점, 시제, 형식, 인물, 시대·장소, 꼭 들어갈 사건과 순서, 결말 조건을 지켰는지 본다. 설정과 어긋나는 내용(이름·관계가 바뀜, 정해 준 결말과 반대)도 실패다. 설정과 어긋나지 않는 지어낸 장면·대사·감정은 문제가 아니다.
- **분량**: 요청에 분량을 적은 사례(설정 메모·참고 글 사례)만 본다. 완성문(뒤에 붙은 사용자용 메모 제외)의 공백을 뺀 글자 수가 사례의 `length` 범위 안이어야 한다. 판정 모델이 아니라 스크립트가 센다. 범위는 요청한 분량(예: 2,000자 안팎, 공백 포함)을 공백 제외로 어림해 넓게 잡았지만 엄격한 편이다.
- **품질 비교**([`draft-fiction-quality.md`](../judge/draft-fiction-quality.md)): 첫 문단부터 이야기 안으로 들어가는지, 누구나 쓸 법한 비유와 교훈조 마무리가 적은지, 장면이 요약으로만 지나가지 않는지, 감정을 이름 붙여 설명하기보다 행동·대사·사물로 드러내는지 본다. 특정 단어의 개수는 세지 않는다.

| 사례 | 입력 | 조건 | 나눔 |
|---|---|---|---|
| `night-shift-brief` | 한두 줄 | 편의점 야간 알바생과 새벽 세 시 손님 | 개발용 |
| `bedding-shop-memo` | 설정 메모 | 1인칭, 사건 순서, 답을 정하지 않는 결말 | 개발용 |
| `tangerine-style` | 동백꽃 + 메모 | 1인칭 아이 화자, 사투리 섞인 구어체 | 개발용 |
| `umbrella-constraint` | 한두 줄 | 대사 없이, 3인칭, 현재형 | 개발용 |
| `vote-ai-brief` | 한두 줄 | 2080년 서울 SF | 확인용 |
| `grandfather-letter-memo` | 설정 메모 | 3인칭, 편지 내용을 다 보여 주지 않는 결말 | 확인용 |
| `rider-style` | 운수 좋은 날 + 메모 | 불행을 암시만 하는 결말, 옛말투 섞인 서술 | 확인용 |
| `letter-form` | 한두 줄 | 서간체 | 확인용 |
| `island-post-brief` | 한두 줄 | 추리 소설 | 새 확인용 |
| `startup-memo` | 설정 메모 | 1인칭, 사건 순서, 다음 날 출근하는 결말 | 새 확인용 |
| `tractor-style` | 동백꽃 + 메모 | 1인칭, 사투리 섞인 구어체 | 새 확인용 |
| `kimchi-two-voices` | 한두 줄 | 두 시점 번갈아, 장면마다 소제목 | 새 확인용 |
| `harbor-dialect-memo` | 설정 메모 | 3인칭, 사건 순서, 부산 사투리 대사, 2,000자 안팎 | 2차 새 확인용 |
| `rooster-school-style` | 동백꽃 + 메모 | 1인칭, 사투리 섞인 구어체, 1,500자 안팎 | 2차 새 확인용 |
| `taxi-style` | 운수 좋은 날 + 메모 | 결말 암시, 옛말투 섞인 서술, 2,000자 안팎 | 2차 새 확인용 |
| `bakery-closing-memo` | 설정 메모 | 3인칭, 사건 순서, 3,000자 안팎 | 2차 새 확인용 |
| `elevator-brief` | 한두 줄 | 분량을 정하지 않음 | 2차 새 확인용 |

한계:

- 사례를 평가 작성자(모델)가 썼다. 실제 사용자의 소설 요청보다 조건이 정돈되어 있다.
- 비교할 사람 소설이 없다. 품질은 판정 모델과 사람 블라인드 비교로만 본다.

## 파일

| 파일 | 내용 |
|---|---|
| [`spec.json`](spec.json) | 사례마다 요청, 입력, 조건, 분량 범위 |
| [`sources.json`](sources.json) | 문체 참고 글 발췌와 출처 |
| [`cases.json`](cases.json) | 위 파일로 만든 사례 |

```bash
node scripts/eval/fiction.mjs sources --dir evals/draft-fiction
node scripts/eval/fiction.mjs build --dir evals/draft-fiction
```
