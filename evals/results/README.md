# 글빨 벤치마크

같은 글쓰기 요청을 글빨을 쓰지 않은 Claude Code와 글빨을 쓴 Claude Code에 주고 결과를 비교했습니다. 사실·조건·말투를 지켰는지, 더 잘 읽히는지, 필요할 때 스킬을 스스로 골랐는지, 시간과 비용이 얼마나 드는지를 따로 봤습니다.

- 실행일: 2026-10-27
- 실행 환경: Claude Code CLI 2.1.311, `claude -p`
- 작성 모델: `claude-sonnet-5-5`
- 판정 모델: `claude-opus-5-5`. 사람의 평가는 하지 않았습니다.

## 2차: 사람이 쓴 글 (글빨 0.3.0)

국내 글쓰기 자료를 조사한 뒤, 2018~2022년에 사람이 쓴 공개 글 10편으로 사례 18개를 만들었습니다. 사례는 두 종류입니다. polish는 사람이 쓴 글을 그대로 다듬는 요청이고, deslop은 다른 모델이 부풀린 글에서 AI 티를 빼는 요청입니다. 개발용 5편으로 스킬을 두 번 고친 뒤 0.3.0으로 고정했고, 확인용 5편으로 결과를 확인했습니다.

| 확인용 사례 9개 × 2회 | 글빨 없음 | 글빨 0.2.1 | 글빨 0.3.0 |
|---|---|---|---|
| 사실·조건·확실성을 지킨 결과 | 8/18 | 16/18 | 16/18 |
| 실행당 시간 중앙값 | 15.3초 | 19.9초 | 22.4초 |

- 글빨 없이 다듬으면 전해 들은 말("가능하다고 합니다")을 단정("가능합니다")으로 바꾸는 경우가 많았습니다. 18개 사례 전체에서 글빨 없음은 36회 중 15회, 0.2.1은 32회 통과했습니다.
- 확인용 사례에서는 0.3.0이 0.2.1보다 낫다는 근거를 얻지 못했습니다. 품질 비교도 3 대 2(같음 5, 엇갈림 4)로 차이가 없었습니다.
- 1차에서 남았던 조건 넓히기 오류와 진단 요청에 대체 문구를 내는 오류는 0.3.0에서 나오지 않았습니다(각 2회 실행). 이 사례들을 보고 고쳤으므로 독립 결과는 아닙니다.
- 판정 모델은 사람 원문보다 고친 글을 거의 항상 골랐습니다. 품질 판정이 모델의 문체를 선호할 수 있습니다.
- 0.3.0은 0.2.1보다 실행당 비용이 약 14% 늘었습니다.

## 1차 결과 한눈에 (모델이 만든 사례, 글빨 0.2)

### 뜻을 지켰는가

판정 모델이 원문과 결과를 대조해, 사실·수치·조건·완료 상태·인용·기술 표기가 바뀌었는지 확인했습니다. 표의 숫자는 이 확인을 통과한 실행 수입니다.

| 사례 | 글빨 없음 | 글빨 0.1.0 | 글빨 0.2.0 |
|---|---|---|---|
| [처음 보는 사례 12개](cases/holdout/README.md) × 2회 | 12/24 | 19/24 | 18/24 |
| [개발 사례 19개](cases/dev/README.md) × 2회 | 28/38 | 37/38 | 36/38 |

처음 보는 사례는 스킬을 고정한 뒤 별도 세션이 만든 자료입니다. 개발 사례는 스킬을 고치는 데 쓴 자료라서 결과가 유리하게 나올 수 있습니다.

**글빨 없이 틀린 예** ([`proposal-warehouse-picking-ko`](cases/holdout/proposal-warehouse-picking-ko.md))

> 원문: 계약 기간(1년 또는 2년, 2년 계약 시 라이선스 10% 할인 조건 제시받음)
>
> 글빨 없음(2회 모두): 계약 기간: 1년 또는 2년(2년 계약 시 라이선스 10% 할인)
>
> 글빨 0.2.0: 계약 기간: 1년 또는 2년 (2년 계약 시 라이선스 10% 할인을 제시받음)

제안받은 단계인 할인이 확정된 계약 조건처럼 바뀌었습니다.

**글빨을 써도 틀린 예** ([`email-conference-speakers-ko`](cases/holdout/email-conference-speakers-ko.md))

> 원문: 해외에 계셔서 현장 참석이 어려우신 경우에는 온라인 발표도 가능합니다.
>
> 글빨 0.2.0: 해외 체류 등으로 현장 참석이 어려우시면 온라인으로 발표하실 수 있습니다.

해외 체류자에게만 허용한 온라인 발표가 다른 사유에도 열린 것처럼 읽힙니다. 글빨 없음에서도 2회 모두 같은 오류가 나왔습니다.

### 더 잘 읽히는가

뜻을 지킨 결과끼리만, 어느 쪽이 글빨인지 숨기고 순서를 바꿔 두 번 비교했습니다. 두 판정이 다르면 승패를 세지 않았습니다.

| 비교 | 처음 보는 사례 | 개발 사례 |
|---|---|---|
| 글빨 0.2.0 대 글빨 없음 | 3 대 1 (같음 2, 엇갈림 6) | 13 대 2 (같음 5, 엇갈림 7) |
| 글빨 0.2.0 대 글빨 0.1.0 | 3 대 3 (같음 5, 엇갈림 6) | 11 대 3 (같음 10, 엇갈림 11) |

- 처음 보는 사례: 비교할 수 있는 쌍이 적고 판정이 자주 엇갈려, 품질 차이는 확인하지 못했습니다.
- 개발 사례: 글빨 쪽이 많이 이겼습니다. 다만 스킬을 고칠 때 쓴 사례라 그대로 믿기는 어렵습니다.

### 알아서 골라 쓰는가

`/geulppal` 없이 평소처럼 요청했을 때 Claude가 스킬을 골랐는지 봤습니다. 요청 22개를 2회씩 실행했습니다.

| 요청 | 스킬을 고른 실행 |
|---|---|
| README 다듬기, AI 티 빼기, 소개글 쓰기 같은 글쓰기 요청 | 24회 중 21회 |
| 코드 구현·수정, 정보 조회, AI 작성 여부 판별 | 20회 중 0회 |

놓친 3회는 모두 영어 요청이었습니다. 요청별 결과는 [자동 선택 결과](2026-10-27-trigger/trigger-v0.2.0-r2.md)에 있습니다.

그 뒤 0.2.1에서 스킬 설명(`description`)에 영어 작업 키워드를 더하고 같은 요청으로 다시 돌렸습니다. 글쓰기 요청 24회 중 23회 골랐고, 코드·조회 요청 20회에서는 고르지 않았습니다([0.2.1 결과](2026-10-27-trigger/trigger-v0.2.1.md)). 이 요청들을 본 뒤 설명을 고쳤으므로 독립 평가 결과는 아닙니다. 스킬 본문은 0.2.0과 같습니다.

### 시간과 비용

글빨을 쓰면 스킬 문서를 읽느라 실행당 비용이 약 2배, 시간이 약 1.3~1.5배 늘었습니다. 처음 보는 사례에서 실행 하나의 시간 중앙값은 글빨 없이 10.0초, 글빨 0.2.0으로 14.1초였습니다. 비용은 CLI가 보고한 API 정가 기준 추정치입니다.

## 이렇게 비교했습니다

- 두 조건의 모델, 요청, 원문, 도구 권한, 출력 조건이 같습니다. 글빨 조건만 프로젝트에 스킬을 두고 요청 앞에 `/geulppal`을 붙였습니다.
- 실행마다 새 세션과 빈 임시 폴더에서 시작했습니다. 개인 설정, 다른 스킬, MCP, 이전 대화는 들어가지 않았습니다.
- 작성 모델에는 요청과 원문만 줬습니다. 평가 기준은 판정 모델에만 줬습니다.
- 글자 수, 금지어 수, AI 탐지기 점수는 품질 점수로 쓰지 않았습니다.

## 한계

- 판정은 모델이 했습니다. 같은 결과를 두 번 판정했을 때 72건 중 4건이 달랐습니다.
