# 글빨 5차 평가 보고서: 메모로 쓰는 업무 글 (2026-10-28)

보고서·보도자료·안내문은 보통 메모나 수치가 든 사실 목록을 주고 써 달라고 한다. 5차에서는 작성 모델에게 요청과 메모만 주고 보도자료·안내문·보고서·기획서를 처음부터 쓰게 했다. 비교한 스킬은 4차에서 고정한 0.4.1이다. 0.4.1을 고친 후보 0.4.2도 시험했지만 채택하지 않았다.

판정은 모델(`claude-opus-5-5`)이 했고, 8쌍은 저장소 소유자가 블라인드로 비교했다.

- **좋아진 것**: 메모로 쓸 때 글빨의 차이가 README보다 컸다. 글빨 없이 쓴 글은 26회 중 17회 근거 판정을 통과하지 못했고, 0.4.1은 2회였다. 글빨 없이 쓴 글의 실패는 다음과 같았다.
  - 메모의 계획(`권고·지도할 계획`)을 시행한 일처럼 확정해 썼다.
  - 메모에 없는 기대 효과("부정수급 경각심 제고와 억지력 강화")나 취지를 붙였다.
  - 서로 다른 통계를 한 조사의 결과처럼 묶었다(접종자 응답 비율을 요양병원 표본 조사의 결과로 씀).
  - 메모에 없는 요일(`27일(화)`)이나 사업 내용을 보탰다.
- **판정 모델의 품질 비교**: 0.4.1이 글빨 없음보다 6 대 0(엇갈림 2)으로 앞섰다. 보도자료 사례에서는 원래 사람 기사보다 5 대 1로 뽑혔다. 이번에는 판정 모델이 사람 기사를 고른 쌍도 있었다.
- **나아지지 않은 것**
  - 0.4.1은 메모의 항목을 순서대로 거의 모두 옮기는 경향이 있었다. 보도자료 첫 문장이 회의를 열었다는 경위로 시작하거나, 보고서 요약에서 지정 서비스 5건 가운데 2건만 꼽는 경우를 판정 모델이 지적했다.
  - 이를 고치려고 문서별 판단에 "메모로 보도자료·안내문·보고서·기획서를 쓸 때"를 넣은 0.4.2 후보를 만들었다. 새 확인용에서 품질은 0.4.1보다 2 대 1(같음 2, 엇갈림 1)로 조금 앞섰지만 근거 판정이 7/10으로 0.4.1(9/10)보다 낮았다. 채택하지 않았다.
  - 0.4.2 후보의 실패에는 메모의 "다음 달"을 실행한 날짜(2026-10-28) 기준으로 "11월"로 확정한 경우가 있었다. 메모의 상대 날짜(지난해, 다음 달)를 오늘 날짜로 풀지 않게 하는 것이 다음 개선 대상이다. 0.4.1도 같은 종류의 정밀도 오류(`등`을 뺌, `7건`을 `7곳`으로 바꿈, 발표일을 고시일로 옮김)를 냈다.
- **채택한 것**: 스킬은 0.4.1을 유지한다. 5차에서 바꾼 것은 평가 자료와 스크립트뿐이다.
- **사람 블라인드 비교**: 저장소 소유자는 0.4.1을 글빨 없음보다 3 대 1(비슷함 1)로 골랐다. 사람 기사와는 1 대 2로 사람 기사를 더 골랐다. 판정 모델은 같은 세 쌍 가운데 두 쌍에서 0.4.1을 골랐으니, 판정 모델과 사람의 선택이 처음으로 갈렸다. 메모로 쓴 보도자료가 사람 기사보다 낫다고는 말할 수 없다. 평가자는 한 명이고 쌍이 적다.
- **확인하지 못한 것**: 회사 내부 보고서·기획서처럼 공공기관 밖의 업무 글.

## 1. 사례

[메모로 쓰는 업무 글 평가](../draft-memo/README.md)에 방법과 자료를 정리했다.

- 기사: 대한민국 정책브리핑 정책뉴스 13편(2018~2022년 게시, 공공누리 제1유형). 본문 텍스트만 쓰고 사진·표는 뺐다.
- 메모: 스킬 없는 별도 세션이 기사를 담당자의 업무 메모로 되돌렸다. 판정 모델이 기사와 대조해 빠지거나 바뀌거나 더해진 사실이 없는 메모만 썼다. 13편 모두 통과했다(2편은 두 번째 시도).
- 요청: 같은 메모로 문서 종류를 정해 써 달라고 했다. 보도자료 4개, 안내문 5개, 보고서 3개, 기획서 1개.
- 나눔: 개발용 4개, 확인용 4개, 새 확인용 5개. 새 확인용은 0.4.2 후보를 고정할 때까지 실행하지 않았다.
- 보도자료 사례에서만 원래 기사를 사람 글(H)로 두고 품질을 비교했다.

## 2. 판정

- **근거 판정**([`draft-memo-claims.md`](../judge/draft-memo-claims.md)): 메모가 유일한 근거다. 결과의 주장(이름, 날짜, 수치, 대상, 조건, 절차, 연락처, 발언, 목적·효과·전망, 향후 계획)마다 메모에서 근거를 찾는다. README 판정과 달리 근거 없는 기대 효과·전망·당부도 실패로 센다.
- **품질 비교**([`draft-memo-quality.md`](../judge/draft-memo-quality.md)): 문서 종류마다 독자가 찾는 것(보도자료는 무엇이 언제 바뀌는지, 안내문은 대상·기한·할 일·문의처, 보고서는 결론과 핵심 수치)을 앞에서 찾을 수 있는지 본다. 순서를 바꿔 두 번 묻고, 두 판정이 같을 때만 센다.

근거 판정은 엄격하다. `등` 하나를 뺀 것, 문의처마다 문의 범위를 붙인 것도 실패로 봤다. 실제 업무에서 문제가 될 정도가 아닌 실패도 섞여 있다.

## 4. 0.4.2 후보 (채택하지 않음)

개발용 결과에서 0.4.1이 메모를 순서대로 모두 옮기고, 보도자료 첫 문장을 경위로 시작하는 점을 보고 [문서별 판단](../../skills/geulppal/references/document-types.md)에 다음을 넣었다.

- 메모의 항목을 모두 옮기는 것이 목표가 아니다. 문서 종류의 독자가 먼저 찾는 것을 앞에 두고, 요청한 분량을 지킨다. 분량 때문에 뺀 사실은 완성문 밖에서 알린다.
- 보도자료는 첫 문장에 결정·변화·시행을, 안내문은 할 일·대상·기한·신청 방법·문의처를, 보고서는 결론과 핵심 수치를, 기획서는 목적·내용·일정·담당을 앞에 둔다.

| | 0.4.1 | 0.4.2 후보 |
|---|---|---|
| 근거 판정, 개발용 4개 × 2회 | 7/8 | 6/8 |
| 근거 판정, 새 확인용 5개 × 2회 | 9/10 | 7/10 |
| 품질 비교(0.4.1 대 0.4.2 후보), 개발용 | 0 대 2 (같음 2, 엇갈림 1) | |
| 품질 비교(0.4.1 대 0.4.2 후보), 새 확인용 | 1 대 2 (같음 2, 엇갈림 1) | |

0.4.2 후보의 새 확인용 실패 3회는 `7건 검출`을 `7곳에서 검출`로 바꾼 것, 배경 설명에서 `등`을 뺀 것, 메모의 "다음 달"을 "11월"로 확정한 것이다. 새 지침이 직접 만든 오류로 보이지는 않지만, 정확성이 낮아진 버전을 올리지 않는다는 기준에 따라 채택하지 않았다.

## 5. 한계

- 메모는 기사에서 거꾸로 만든 것이라 실제 메모보다 정리되어 있고, 기사의 순서를 따른다. 기사에 있는 사실을 거의 다 담아서, 사람 기사(H)와의 비교에서 작성 모델이 유리할 수 있다.
- 정책 기사라서 공공기관 문서에 치우쳐 있다. 안내문·보고서·기획서는 사람이 쓴 같은 장르의 글이 없어 사람 글과 비교하지 않았다.
- 근거 판정이 엄격해 사소한 차이도 실패로 센다. 반대로 판정 모델이 놓친 오류가 있을 수 있다.
- 사례가 13개로 작다. 판정 모델은 같은 회사의 모델이다.
