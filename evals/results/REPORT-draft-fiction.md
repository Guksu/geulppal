# 글빨 7차 평가 보고서: 짧은 소설 (2026-10-30)

마지막 장르로 짧은 소설을 평가했다. 소설은 지어낸 이야기라서 "입력에 없는 내용을 쓰지 않았는가"로 평가할 수 없고, 비교할 정답 원문도 없다. 그래서 요청한 조건과 설정을 지켰는지(조건 판정)와 요청한 분량을 확인하고, 품질은 짝 비교와 사람 블라인드 비교로 본다. 블로그 평가에서 넣은 "입력에 없는 장면을 쓰지 않는다" 규칙(0.4.3)이 소설을 메마르게 하지 않는지도 확인했다.

작성 모델은 `claude-sonnet-5-5`, 실행 환경은 Claude Code CLI 2.1.314다(세 실행 모두 같은 버전). 판정은 모델(`claude-opus-5-5`)이 했다. 저장소 소유자 한 명이 블라인드로도 비교했다.

## 요약

|---|---|---|
| 조건 판정(분량 제외), 확인용+새 확인용 8개 | 12/16 | 10/16 |
| 요청한 분량 안에 든 결과(분량을 요청한 6개) | 3/12 | 5/12 |
| 조건 판정+분량, 확인용+새 확인용 8개 | 10/16 | 7/16 |
| 공백 뺀 글자 수 평균(확인용 / 새 확인용) | 1,309자 / 1,586자 | 1,056자 / 1,162자 |

- **좋아진 것**: 판정 모델은 소설에서 0.4.3을 글빨 없음보다 10 대 0으로 골랐다(같음·엇갈림 없음). 판정 이유는 감정을 이름 붙여 설명하지 않고 사물과 행동으로 보여 준다("오래 쥐던 사람의 손가락이 만든 홈이라, 서진의 손에는 조금 크다"), 결말을 정리하거나 교훈으로 닫지 않는다는 것이었다.
- **걱정했던 것**: 0.4.3은 소설을 짧게 썼다. 분량을 정하지 않은 한두 줄 입력 사례 6개(12회)에서 공백 뺀 글자 수 평균이 글빨 없음은 1,618자, 0.4.3은 962자였고, 6개 사례 모두 0.4.3이 더 짧았다. 블로그용 규칙("입력이 한두 줄이면 그만큼 짧게 쓴다")이 소설에도 적용된 것으로 보인다. 그래도 판정 모델과 사람 블라인드 비교 모두 짧은 쪽을 더 골랐다.
- **사람 블라인드 비교**: 저장소 소유자는 0.4.3을 5 대 1(비슷함 2)로 골랐다. 판정 모델과 판단 방향이 같았다. 사람 글과 비교한 블로그·보도자료에서는 둘이 갈렸지만, 소설에는 비교할 사람 글이 없다. 다만 판정 모델이 함께 비교한 4쌍에서 판정 모델은 모두 0.4.3을, 사람은 2쌍에서 0.4.3을, 2쌍에서 비슷함을 골라 차이는 판정 모델만큼 크지 않았다.
- **나아지지 않은 것**
  - 조건을 지키는 정도는 비슷하거나 조금 낮았다. 0.4.3은 "사투리 섞인 말투"를 요청받고 표준어로 쓰거나(2회), "50대", "서울" 같은 설정을 본문에 드러내지 않았다. 글빨 없음도 같은 사례에서 사투리를 빠뜨렸다.
  - 두 조건 모두 요청한 분량("2,000자 안팎")보다 20%가량 짧게 썼다.
  - 「운수 좋은 날」을 문체 참고로 줬을 때 두 조건 모두 "오래간만에도 닥친 운수 좋은 날이었다" 같은 참고 글의 문장을 단어만 바꿔 옮겼다.
- **0.4.5 후보 (채택하지 않음)**: 소설에는 자기 경험 글 규칙을 적용하지 않고, 정해 준 설정·분량을 본문에서 지키고, 참고 글의 문장을 옮기지 않게 했다. 개발용에서 한두 줄 입력의 분량은 늘었지만 요청한 분량은 여전히 못 맞췄고, 품질 비교에서 0.4.3에 1 대 3으로 밀렸으며 조건 판정도 7/8로 0.4.3(8/8)보다 낮았다.
- **채택한 것**: 스킬은 0.4.3을 유지한다. 7차에서 바꾼 것은 평가 자료와 스크립트뿐이다.

## 1. 사례

[짧은 소설 평가](../draft-fiction/README.md)에 방법과 자료를 정리했다.

- 사례 12개를 실행 전에 직접 썼다. 개발용 4개, 확인용 4개, 새 확인용 4개.
- 입력은 세 가지다: 한두 줄 설명(일부는 대사 없이·현재형·편지·두 시점 같은 형식 조건), 설정 메모(인물 이름·나이·관계, 배경, 사건 순서, 시점, 결말, 분량), 문체 참고 글 + 설정 메모.
- 문체 참고 글은 김유정 「동백꽃」(1936)과 현진건 「운수 좋은 날」(1924)의 앞부분이다. 두 작가 모두 저작권 보호기간이 끝났다.

## 2. 판정

- **조건 판정**([`draft-fiction-check.md`](../judge/draft-fiction-check.md)): 시점, 시제, 형식, 인물, 시대·장소, 꼭 들어갈 사건과 순서, 결말 조건을 지켰는지, 설정과 어긋나는 내용이 없는지 본다. 지어낸 장면·대사·감정은 문제가 아니다.
- **분량**: 요청에 분량을 적은 사례만, 공백을 뺀 글자 수가 범위 안인지 스크립트가 센다.
- **품질 비교**([`draft-fiction-quality.md`](../judge/draft-fiction-quality.md)): 첫 문단부터 이야기 안으로 들어가는지, 누구나 쓸 법한 비유와 교훈조 마무리가 적은지, 장면이 요약으로만 지나가지 않는지, 감정을 행동·대사·사물로 드러내는지 본다. 두 결과가 모두 조건 판정을 통과한 쌍만 비교했다.

**실행 뒤에 고친 기준**: 처음에는 분량을 요청하지 않은 한두 줄 입력 사례 6개에도 분량 범위를 판정에 넣었다. 요청하지 않은 분량으로 실패 처리하는 것은 공정하지 않아, 요청에 분량을 적은 사례만 분량을 보도록 고쳤다. 기준선 판정을 본 뒤에 고쳤고, 두 조건에 똑같이 다시 계산했다(0.4.3의 2회가 실패에서 통과로 바뀜). 판정 모델의 답은 바꾸지 않았다.

## 5. 한계

- 사례를 평가 작성자(모델)가 썼다. 실제 사용자의 소설 요청보다 조건이 정돈되어 있다.
- 비교할 사람 소설이 없다.
- 사람 블라인드 비교의 평가자는 한 명이고 8쌍뿐이다. 비교할 사람 소설이 없어 글빨 없음과만 비교했다.
- 분량 범위(공백 제외)는 실행 전에 정했지만 엄격한 편이다.
- 분량 스크립트는 처음에 첫 구분선(`---`) 앞까지만 셌다. 장면을 `---`로 나눈 결과(`island-post-brief` 글빨 없음 1회)가 짧게 세어져, 마지막 구분선 뒤의 짧은 메모만 빼도록 고쳤다. 이 결과는 분량을 요청하지 않은 사례라 통과·실패는 바뀌지 않았고, 분량을 요청한 사례의 글자 수도 그대로다. 위 글자 수는 고친 방식으로 셌다.

## 6. 후속: 분량·말투 후보 0.4.6 (2026-10-31, 채택하지 않음)

7차에서 남은 분량 미달, 사투리 누락, 참고 글 베끼기를 고치려고 0.4.6 후보(`v0.4.6-r1`, 조건 이름 L1)를 만들었다. 후보를 만들기 전에 2차 새 확인용 5개를 추가하고 커밋했다. 실행 환경은 7차와 같은 CLI 2.1.314다.

0.4.3에 더한 것:

- 소설에는 자기 경험 글 규칙(7번) 대신 소설 규칙을 따른다. 정해 준 설정은 본문에서 지키고 나머지 장면·대사는 지어 쓴다.
- 정해 준 분량은 공백 포함으로 세고, 짧아지기 쉬우므로 조금 넘길 만큼 장면을 계획한다. 모자란 분량은 요약으로 지나간 대목을 장면으로 풀어 채우고, 첫머리의 인물 소개나 배경 설명을 늘리지 않는다(0.4.5 후보가 품질 비교에서 진 이유).
- 정해 준 말투는 대사와 서술 어미에 끝까지 드러나게 쓰고, 사투리·옛말투는 맞춤법 오류가 아니라고 적었다.
- 참고 글의 문장 틀에 명사만 바꿔 넣지 않는다.

| 실행당 비용(USD), 2차 새 확인용 | 0.068 | 0.107 | 0.140 |

- **분량**: 0.4.6 후보는 요청한 분량에 가깝게 썼다(2차 새 확인용 83~104%, 0.4.3은 59~88%).
- **말투**: 참고 글 없이 부산 사투리 대사를 요청한 사례는 세 조건 모두 통과했다. 「동백꽃」 말투를 따르라는 `rooster-school-style`은 0.4.3과 0.4.6 후보가 2회 모두 표준어로 써서 실패했다(글빨 없음은 1회 통과). 사투리 규칙은 효과를 확인하지 못했다.
- **참고 글 베끼기**: 「운수 좋은 날」 문장을 옮긴 결과는 0.4.3 1회(`taxi-style`), 0.4.6 후보 0회였다. 횟수가 적어 차이라고 하기 어렵다.
- **설정 누락**: 세 조건 모두 메모의 장소(대전, 강원도 산골 분교)를 본문에 드러내지 않은 경우가 있었다.

품질 비교(판정 모델). 2차 새 확인용에서 둘 다 조건 판정+분량을 통과한 쌍이 한 줄 입력 사례 2쌍뿐이라, 분량을 빼고 나머지 조건을 통과한 쌍끼리 따로 비교했다(`judge.mjs pair --ignore-length`, 기록은 `judge/pair-nolength/`).

| 0.4.3 대 0.4.6 후보 | 2 대 2 (같음 1, 엇갈림 1) | 1 대 1 | 3 대 1 (엇갈림 2) |
| 글빨 없음 대 0.4.6 후보 | 0 대 3 (엇갈림 1) | 0 대 2 | 0 대 5 (엇갈림 1) |

판정 모델은 0.4.3을 더 골랐다. 이유는 0.4.6 후보가 길어진 만큼 흔한 비유, 위로를 직접 말하는 대사, 의미를 정리하는 결말 문장이 늘었다는 것이었다. 한편 7차 사람 블라인드 비교에서 0.4.3이 진 한 쌍은 0.4.3이 요청한 분량보다 짧았던 사례였다. 판정 모델의 절제 선호와 독자의 선호가 다를 수 있어, 0.4.3과 0.4.6 후보를 사람 블라인드로도 비교했다(개발용 4쌍, 2차 새 확인용 5쌍). 저장소 소유자는 0.4.6 후보 2, 0.4.3 2, 비슷함 5로 골랐다([블라인드 비교](2026-10-31-draft-fiction-l1-rating/report.md)). 분량은 나아졌지만 읽는 사람이 느낄 만한 차이는 없었고, 사투리 문제는 고치지 못했으며, 실행당 비용은 약 30% 늘었다. 그래서 채택하지 않고 0.4.3을 유지한다.

**블로그 회귀 확인**: 0.4.6 후보는 블로그 규칙을 바꾸지 않았지만 같은 `새 글 쓰기` 절을 고쳤으므로 블로그 2차 새 확인용 4개를 다시 실행했다. 근거 판정은 0.4.3 4/8, 0.4.6 후보 6/8이고, 근거 없는 내용은 0.4.3 6개, 0.4.6 후보 3개였다. 0.4.3은 같은 사례에서 CLI 2.1.312로 7/8이었으므로 실행에 따른 변동이 크다.
