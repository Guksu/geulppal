# 글빨 3차 평가 보고서: 사람이 쓴 README와 남은 오류 (2026-10-27)

2차 평가의 사람 글은 정책브리핑 기사여서, 글빨의 주 용도인 README와 장르가 달랐다. 3차에서는 세 가지를 했다.

1. ChatGPT 공개(2022-11-30) 전에 사람이 쓴 한국어 오픈소스 README로 사례 16개를 만들어, 글빨 없음·0.2.1·0.3.0을 비교했다.
2. 0.3.0에 남은 오류(추측·정도 표시가 약해지거나 사라짐)를 줄이는 후보 0.3.1을 시험했다.
3. 판정 모델 대신 사람이 고르는 블라인드 비교 페이지를 만들었다.

판정은 모두 모델(`claude-opus-5-5`)이 했다. 블라인드 비교는 아직 평가를 받지 않았다.

- **확인하지 못한 것**

## 2. 남은 오류 줄이기: 0.3.1 후보

0.3.0의 실패는 대부분 작성자의 판단 표시가 약해지거나 사라진 경우였다. 추측(`~ㄹ 것이다`), 정도(`다소`, `조금`), 범위(`만`)를 나타내는 말이다. 2차 개발용과 README 개발용의 실패만 보고 완성 점검에 항목 하나를 넣었다.

> 원문과 문장 단위로 맞춰 볼 때, 전해 들은 말, 추측·의견, 정도(`다소`, `조금`, `대부분`, `핵심`), 범위(`만`, `등`, `모두`)를 나타내는 말이 같은 강도와 시제로 남았는가? 정도를 나타내는 말은 군더더기처럼 보여도 작성자의 판단이다.

2차 확인용 사례에서 본 실패 문구(`~텐데`, `기대된다`)는 예시로 쓰지 않았다. 후보는 한 라운드만 만들고 확인용 실행 전에 고정했다(`3b77355`, `evals/snapshots/v0.3.1-r1`).

| 의미 보존 | 0.3.0 | 0.3.1 후보 |
|---|---|---|
| 사람 글 개발용 | 16/18 | 16/18 |
| README 개발용 | 15/16 | 16/16 |
| 사람 글 확인용 | 16/18 | 17/18 |
| README 확인용 | 16/16 | 15/16 |

| 품질 비교(확인용) | 0.3.0 대 0.3.1 후보 |
|---|---|
| 사람 글 | 0 대 2 (같음 5, 엇갈림 8) |
| README | 1 대 2 (같음 6, 엇갈림 6) |

사람 글 확인용 결과는 독립 결과가 아니다. 2차 보고서를 쓰며 이 사례의 0.3.0 실패 내용을 봤기 때문이다. README 확인용 결과는 후보를 만들 때 보지 않은 자료다.

0.3.1 후보의 확인용 실패 2회는 둘 다 새 누락이었다.

- 방문기의 "실감 나게 볼 수 있을 것으로 기대된다"를 근거 없는 문장이라며 지운 경우
- 소개글의 "짧은 트윗부터 긴 글까지"를 "짧은 트윗 같은 글"로 좁힌 경우

노린 오류 종류는 줄었지만 전체 실패 수는 그대로였다. 품질 차이도 작아 채택하지 않았다. 실행당 비용은 0.3.0과 비슷했다(0.097~0.098 USD).

## 3. 사람 블라인드 비교

판정 모델이 사람 원문보다 모델이 고친 글을 거의 항상 고르므로, 품질 판단은 사람이 직접 해야 한다. 2차 사람 글 사례에서 22쌍을 골라 블라인드 비교 페이지를 만들었다(`scripts/eval/rating.mjs`).

- 쌍의 구성
  - 글빨 없음 대 0.3.0: 11쌍
  - deslop 사례의 사람 원문 대 0.3.0: 7쌍
  - 0.2.1 대 0.3.0: 4쌍
- 두 결과가 모두 의미 보존을 통과한 쌍만 골랐다.
- 페이지에는 요청·원문·결과 두 개만 있다. 어느 쪽이 어떤 조건인지는 로컬 파일에만 있다.
- 평가가 모이면 `rating.mjs score`로 판정 모델의 판단과 맞춰 본다. 아직 받은 평가가 없다.
