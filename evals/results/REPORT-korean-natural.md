# 글빨 8차 평가 보고서: 한국어 답변의 자연스러움 (2026-10-31~11-03)

글빨의 방향을 처음 의도로 되돌렸다. Claude가 쓴 한국어에서 사람들이 쓰지 않는 말과 어색한 문장을 다듬는 것이다. 0.4까지의 평가는 뜻을 바꾸지 않는지, 지어내지 않는지만 쟀고, 그 평가에서 나온 한국어 결과 1,318개에는 `조용한 실패` 같은 표현이 한 번도 나오지 않았다. 그래서 Claude가 개발 작업 중에 실제로 쓰는 한국어 답변으로 새 평가를 만들었다.

작성 모델은 `claude-sonnet-5-5`, 판정 모델은 `claude-opus-5-5`다. 실행 환경은 첫 평가가 Claude Code CLI 2.1.316, 새 확인용이 2.1.317이고, 한 표 안의 조건은 모두 같은 버전으로 실행했다.

## 요약

| | 글빨 없음 | 0.4.3 | 0.5.0 | 0.5.1 |
|---|---|---|---|---|
| 쓰기: 표시된 곳, 질문 16개 × 2회 | 74 | 68 | 50 | |
| 쓰기: 표시된 곳, 새 확인용 8개 × 2회 | 34 | | 45 | 36 |
| 다듬기: 결과 1개당 표시된 곳(다듬기 전 2.1곳), 새 확인용 8개 × 2회 | 2.38 | | 1.62 | 1.50 |
| 다듬기: 원래 표시된 표현이 그대로 남은 수 | 19/34 | | 8/34 | 4/34 |
| 다듬기: 뜻을 지킨 결과 | 12/16 | | 16/16 | 16/16 |

- **다듬기에서는 효과가 분명했다.** 글빨 없이 다듬으면 어색한 표현이 절반 넘게 남고 16개 중 4개는 뜻이 바뀌었다(`메모리도 씁니다` → `메모리도 많이 씁니다`). 0.5.1은 글 길이를 거의 그대로 두고 표시된 표현 34개 중 30개를 고쳤으며, 뜻은 모두 지켰다.
- **처음부터 쓰게 할 때는 효과를 확인하지 못했다.** 첫 질문 16개에서는 0.5.0이 표시를 74곳에서 50곳으로 줄였지만, 답이 22% 짧아진 영향이 컸다(1,000자당 0.72곳 → 0.62곳). 결과를 보기 전에 만든 새 질문 8개에서는 글빨 없음 34곳, 0.5.0 45곳, 0.5.1 36곳으로 줄지 않았다.
- **고친 것과 새로 생긴 것.** 글빨 없는 답에 많던 `조용히 넘어갑니다`, `조용히 걸러집니다` 같은 표현은 0.5.1에서 사라졌다. 대신 업계에서 영어 그대로 부르는 말을 우리말로 바꾸거나(React의 effect → `효과`, feature → `특징`), 표에 없는 비유(`무한 루프의 씨앗`)를 쓰는 일이 생겼다. feature → `특징`과 `싸다`는 0.5.1 규칙과 표에 적어 둔 말인데도 남았다.
- **채택한 것**: 0.5.1(`v0.5.1-r2`). 새 확인용 쓰기와 다듬기 모두 0.5.0보다 표시가 적었다. 쓸 때보다 다 쓴 답을 다듬게 할 때 효과가 있으므로, 사용 안내에 이 방법을 먼저 적는다.

## 1. 사례

[한국어 자연스러움 평가](../korean-natural/README.md)에 방법을 정리했다.

- 작업 폴더에 README 초안 평가와 같은 공개 저장소 코드(2022-11-30 이전 커밋)를 넣고, 개발자가 흔히 하는 질문을 한국어로 했다. 질문은 동작 설명, 오류 처리, 리뷰, 설계 이유, 테스트 계획 다섯 가지다.
- 질문 16개(개발용 6개, 확인용 10개)는 0.5.0을 커밋한 뒤, 결과를 보기 전에 썼다.
- 0.5.0 결과를 본 뒤 다음 후보를 만들기 전에, 새 질문 네 가지(성능, 최신 버전으로 올리기, 파일별 정리, 버그가 숨은 곳)로 새 확인용 8개를 더해 커밋했다.
- 다듬기 사례는 글빨 없이 쓴 답변(사례마다 1회차)을 "내용은 그대로 두고 한국어로 자연스럽게 다듬어 줘"라고 다시 맡긴 것이다. 0.5.1의 표에 더한 표현 일부가 첫 질문의 답변에서 본 것이어서, 0.5.1의 다듬기는 새 확인용 답변으로 만든 사례로만 확인했다.

## 2. 판정

- [`korean-natural.md`](../judge/korean-natural.md): 판정 모델이 글을 읽고, 이 저장소를 처음 보는 한국어 개발자가 멈칫할 곳을 표시한다. 종류(낱말대로 옮긴 말, 설명 없는 이름, 명사 나열, 기호로 대신한 설명, 번역투, 그 밖의 어색함)와 정도를 적는다. 업계에서 그대로 쓰는 외래어, 코드 이름, 취향 차이는 표시하지 않는다. 같은 표현이 여러 번 나와도 한 번으로 센다.
- 다듬기는 [의미 보존 판정](../judge/meaning.md)도 함께 했다.
- 표시된 곳의 수는 글의 품질 점수나 AI 작성 확률이 아니다. 이 스킬이 고치려는 표현이 남았는지 보는 근거로만 쓴다.

## 3. 결과

### 쓰기

| | 글빨 없음 | 0.4.3 | 0.5.0 | 0.5.1 |
|---|---|---|---|---|
| 질문 16개 × 2회: 표시된 곳 | 74 | 68 | 50 | |
| 같은 결과: 1,000자당 | 0.72 | 0.74 | 0.62 | |
| 같은 결과: 표시가 없는 답변 | 3/32 | 1/32 | 6/32 | |
| 새 확인용 8개 × 2회: 표시된 곳 | 34 | | 45 | 36 |
| 같은 결과: 1,000자당 | 0.69 | | 1.00 | 0.80 |
| 같은 결과: 표시가 없는 답변 | 3/16 | | 0/16 | 3/16 |

0.4.3은 글빨 없음과 거의 같았다. 0.4까지의 글빨은 이 문제를 다루지 못했다.

0.5.0이 고친 것과 남긴 것:

- 글빨 없는 답에서 표시된 예: `진실의 원천이 둘`, `URL이 스텝의 단일 진실 공급원이고`, `커버리지가 매우 얇습니다`, `구현 위생 문제가 보입니다`, `오염된 데이터에 견고합니다`.
- 0.5.0은 업계에서 영어 그대로 부르는 말을 우리말로 바꾸는 문제를 새로 만들었다. key → `열쇠`, fixture → `준비물`, processor → `처리기`, feature → `특징`. 첫 질문에서 0.5.0이 표시된 50곳 가운데 열 곳 넘게 이 경우였다.
- 스킬 표에 적어 둔 `조용히 실패한다`도 `조용히 사라집니다`처럼 모양을 바꿔 세 번 남았다.

0.5.1에서 바꾼 것(0.5.0에서 출발):

- 독자가 영어 그대로 부르는 말은 낱말 뜻으로 옮기지 않는다(key, fixture, target, feature, resolve).
- `조용히`가 붙은 다른 말도 같은 경우로 다루고, 영어식 비유(`타입이 거짓말을 한다`, `비용을 낸다`, `커버리지가 얇다`)를 표에 더했다.
- [오웰의 글쓰기 원칙](../../research/orwell.md)에서 가져와, 표에 없는 말도 "실제로 말하려는 일을 정하고 독자가 평소에 쓰는 말로 쓰는" 순서로 고치게 했다. 과장 표에 익숙한 비유, 번역투 표에 겹피동을 더했다.
- 처음 만든 0.5.1-r1은 새 확인용 실행이 사용량 한도로 모두 실패해 결과가 없다. 실행하기 전에 오웰의 질문을 더한 r2로 바꿨으므로, 두 변경의 효과를 따로 가를 수 없다.

새 확인용에서 0.5.1은 `조용히` 계열을 모두 고쳤지만, React의 effect를 `효과`로, feature를 `특징`으로 쓰는 일이 남았다. 표에 없는 비유(`무한 루프의 씨앗`, `예외가 새어 나옵니다`)가 새로 나왔고, 표에 적어 둔 `싸다`도 `가장 쌉니다`로 한 번 남았다.

### 다듬기

| 새 확인용 답변 8개 × 2회 | 글빨 없음 | 0.5.0 | 0.5.1 |
|---|---|---|---|
| 결과 1개당 표시된 곳(다듬기 전 8개 합계 17곳, 1개당 2.1곳) | 2.38 | 1.62 | 1.50 |
| 다듬기 전에 표시된 표현이 그대로 남은 수 | 19/34 | 8/34 | 4/34 |
| 뜻을 지킨 결과 | 12/16 | 16/16 | 16/16 |
| 평균 글자 수(공백 제외, 입력 3,197자) | 3,227 | 3,228 | 3,225 |

글빨 없이 다듬으면 뜻이 바뀐 결과가 4개였다. 5.x로 가는 단계를 지운 경우, `메모리도 씁니다`에 `많이`를 보탠 경우, `이 연결은`을 `이때 연결은`으로 바꿔 문제가 생기는 조건을 좁힌 경우(2회)다.

첫 질문의 답변 16개로 만든 다듬기 사례에서도 글빨 없이 다듬으면 표시가 거의 줄지 않았고(1개당 2.44곳 → 2.28곳), 32개 중 6개는 뜻이 바뀌었다(`달라집니다` → `달라질 수 있습니다` 등). 이 사례의 0.4.3과 0.5.0 판정은 사용량 한도로 하지 못했다.

## 4. 한계

- 판정 모델 하나가 표시했다. `핀`(버전 고정), `진행 막대`처럼 사람에 따라 괜찮다고 볼 표현도 표시했다. 판정 모델의 표시가 사람의 감각과 맞는지 확인하는 짧은 문장 확인(10개)은 아직 하지 않았다.
- 조건마다 결과가 16~32개라 작은 차이(34곳과 36곳)는 판정의 흔들림과 구별하기 어렵다.
- 질문과 다듬기 요청은 평가 작성자(모델)가 썼다. 공개 저장소 코드에 대한 개발 질문만 다뤘고, 일상 대화나 일반 문서는 다루지 않았다.
- 0.5에서 새로 쓸 때의 내용 규칙을 참고 문서로 옮긴 뒤, README·보고서 초안 평가는 다시 하지 않았다.
