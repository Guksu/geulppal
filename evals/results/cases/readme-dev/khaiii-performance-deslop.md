> # 성능
>
> ## 정확도
>
> ### v0.3
>
> CNN 모델의 성능을 좌우하는 핵심 하이퍼 파라미터는 두 가지입니다. 하나는 분류하려는 음절의 좌/우 문맥 크기를 나타내는 `win`, 다른 하나는 음절 임베딩의 차원을 나타내는 `emb`입니다. `win`은 {2, 3, 4, 5, 7, 10} 중에서, `emb`는 {20, 30, 40, 50, 70, 100, 150, 200, 300, 500} 중에서 값을 선택합니다. 두 값의 조합은 6 x 10, 총 60가지이며, 이를 모두 실험해 성능을 비교했습니다. 성능 지표로는 정확률과 재현율의 조화 평균인 F-Score를 사용했습니다.
>
> 실험 결과에서 몇 가지 경향이 보였습니다.
>
> * **`win`**: 3 혹은 4에서 가장 좋은 성능을 보였고, 그보다 커지면 오히려 성능이 떨어졌습니다.
> * **`emb`**: 150까지는 값이 커질수록 성능도 함께 높아졌지만, 그 이상에서는 뚜렷한 차이가 없었습니다.
>
> 상위 5위 모델 중 비교적 크기가 작은 모델은 `win=3`, `emb=150`이며 F-Score는 97.11입니다. 우리는 이 모델을 **large 모델**이라 부르기로 했습니다.
>
> ### v0.4
>
> \[띄어쓰기 오류에 강건한 모델을 위한 실험](https://github.com/kakao/khaiii/wiki/%EB%9D%84%EC%96%B4%EC%93%B0%EA%B8%B0-%EC%98%A4%EB%A5%98%EC%97%90-%EA%B0%95%EA%B1%B4%ED%95%9C-%EB%AA%A8%EB%8D%B8%EC%9D%84-%EC%9C%84%ED%95%9C-%EC%8B%A4%ED%97%98)을 통해 모델을 한 단계 개선했습니다. v0.4 모델은 띄어쓰기가 잘 되어 있지 않은 입력에서 한층 좋은 성능을 보입니다. 다만 그 대가로 세종 코퍼스에서의 정확도는 다소 떨어졌습니다. 이 점을 보완하기 위해 base 모델과 large 모델의 파라미터를 다음과 같이 조정했습니다.
>
> * **base 모델**: `win=4`, `emb=35`, F-Score 94.96
> * **large 모델**: `win=4`, `emb=180`, F-Score 96.71
>
> ## 속도
>
> ### v0.3
>
> 모델이 커지면 정확도는 높아지지만, 그만큼 계산량도 늘어 속도는 느려집니다. 그래서 적당한 정확도를 유지하면서 크기가 작아 빠른 모델을 **base 모델**로 선정했습니다. F-Score가 95 이상인 모델 중 크기가 가장 작은 것은 `win=3`, `emb=30`이며, F-Score는 95.30입니다.
>
> 속도 비교를 위해 1만 문장(총 903KB, 문장 평균 91)의 텍스트를 분석하고 걸린 시간을 측정했습니다. base 모델은 약 10.5초, large 모델은 약 78.8초가 걸렸습니다.
>
> ### v0.4
>
> v0.4에서는 모델의 크기가 커진 만큼 base 모델과 large 모델의 속도를 다시 측정했습니다. 그 결과 v0.3보다 다소 느려졌습니다.
>
> * **base 모델**: 10.8 -> 14.4
> * **large 모델**: 87.3 -> 165
