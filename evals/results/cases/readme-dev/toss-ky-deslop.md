## 원문

> # @toss/ky
>
> **CJS와 ESM, 어디서든 막힘없이 쓰는 \[ky](https://github.com/sindresorhus/ky).**
>
> `@toss/ky`는 \[ky](https://github.com/sindresorhus/ky) 라이브러리를 CJS와 ESM 환경 모두에서 호환되도록 만든 라이브러리입니다. 모듈 방식 때문에 고민할 필요 없이, 익숙한 `ky`를 그대로 가져다 쓸 수 있습니다.
>
> 사용법은 `ky`와 동일합니다. 자세한 내용은 \[ky 문서](https://github.com/sindresorhus/ky)를 참고해 주세요.
>
> ```shell
> $ node
> > require("@toss/ky")
> # -> 가능
>
> > await import("@toss/ky")
> # -> 가능
> ```
>
> ## 왜 필요한가요?
>
> `ky`는 훌륭한 라이브러리이지만, 실제 프로젝트에 적용하다 보면 다음과 같은 걸림돌을 만나게 됩니다.
>
> - **ESM-only 라이브러리입니다.** CJS 환경에서 `require()`로 불러오려 하면 오류가 발생합니다.
> - **SSR 대응이 번거롭습니다.** 서버 사이드 렌더링을 지원하려면 별도로 `ky-universal` 라이브러리를 사용해야 합니다.
>
> `@toss/ky`는 이 문제들을 다음과 같이 해결해, `ky`를 훨씬 편하게 사용할 수 있도록 돕습니다.
>
> - **하나의 패키지로 CJS와 ESM을 모두 지원합니다.** ESBuild로 한 차례 빌드해, 어떤 모듈 방식에서도 동일하게 사용할 수 있습니다.
> - **서버와 클라이언트를 구분하지 않아도 됩니다.** `ky-universal`을 쓸지 `ky`를 쓸지 고민할 필요 없이, `@toss/ky` 하나만 사용하면 됩니다.
>
> ## 왜 빌드된 결과물이 소스코드에 포함되어 있나요?
>
> 저장소를 살펴보다 보면 빌드된 결과물이 소스코드에 함께 포함되어 있는 것을 발견하실 수 있습니다. 여기에는 이유가 있습니다.
>
> - **Jest 등의 테스트 환경에서 발생하는 오류를 피하기 위해서입니다.** 빌드된 결과물을 소스코드에 포함하지 않으면, frontend-libraries 내부에서 Jest 등을 실행할 때 내부적으로 `require('ky')`가 실행되어 `ERR_REQUIRE_ESM` 오류가 발생합니다. 이를 해결하기 위해 불가피하게 `ky`를 빌드된 상태로 소스코드에 포함했습니다.
> - **빌드된 결과물을 업데이트하려면** `ky` 디렉토리에서 `yarn build`를 실행한 뒤, 변경사항을 커밋해 주세요.
