# 평가

`cases.json`은 글쓰기 품질과 의미 보존을 확인하기 위한 입력이다. 모든 제품·수치·사례는 평가용 가상 자료다. 공개 연구와 과거 README는 설계에 사용했으므로 독립적인 평가 자료로 취급하지 않는다.

## 실행 방법

같은 모델·버전·설정에서 스킬이 없는 조건과 있는 조건에 각 사례를 새 대화로 전달한다. 작성 작업에는 `request`와 `input`만 전달한다. `must_preserve`와 `must_not`은 결과를 평가할 때 사용한다. 자동 선택 평가에는 스킬 설명과 실제 등록 환경이 필요하다. 본문을 직접 붙여 넣은 실행을 자동 선택 성공으로 기록하지 않는다.

결과를 A/B로 가리고 순서를 바꿔 비교한다. 한 사람이 모든 결과를 평가하면 그 사실을 기록한다. 가능하다면 실제 문서 독자에게 어느 결과가 더 명확한지와 그 이유를 묻는다. 더 짧은 글이나 AI 탐지기 점수가 낮은 글을 자동으로 선택하지 않는다.

## 판정

먼저 사실·수치의 의미·조건·상태·인용·기술 표기 손상이 있는지 확인한다. 하나라도 바뀌면 의미 보존 실패다. 표현이 매끄럽다는 이유로 이를 상쇄하지 않는다.

의미가 보존된 결과끼리 다음을 비교한다.

- 필요한 정보와 요청 행동을 쉽게 찾을 수 있는가?
- 구체적인 의미가 없는 문장과 반복이 줄었는가?
- 어색한 단문 나열이나 억지 구어체가 생기지 않았는가?
- 독자·장르·작성자 말투에 맞는가?
- 충분히 좋은 원문을 불필요하게 바꾸지 않았는가?

각 판정에 실제 문장을 근거로 남긴다. 전후 글자 수는 참고 정보이며 합격 기준이 아니다. 결과에는 모델 식별자·날짜·설정·스킬 커밋·입력·출력·실패 이유를 함께 보관한다. 단일 실행의 결과는 해당 사례의 관찰로만 설명한다.

## 현재 상태

사례를 작성하고 파일 구조를 확인했다. Claude의 스킬 자동 선택, 스킬 유무 비교 실행, 독립적인 독자 평가는 아직 수행하지 않았다. 이 사례 목록을 통과한 테스트 수나 효과 입증으로 소개하지 않는다.
