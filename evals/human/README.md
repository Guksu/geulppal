# 사람이 쓴 글 평가

기존 평가 사례는 모두 모델이 만든 가상 문서였다. 여기서는 2024년 이전에 사람이 쓴 공개 글로 두 가지를 확인한다.

- **polish**: 사람이 쓴 글을 그대로 주고 다듬어 달라고 한다. 이미 읽을 만한 글을 필요 이상으로 고치지 않는지, 작성자의 말투와 전해 들은 말·추측·의견 표시를 지키는지 본다.
- **deslop**: 같은 글을 다른 모델이 "더 전문적이고 매력적으로" 고친 결과를 주고 AI 티를 빼 달라고 한다. 덧붙은 과장과 형식을 덜어내면서 사실을 지키는지 본다. 사람이 쓴 원문은 작성 모델에게 주지 않는다.

조사 배경과 원문을 고른 기준은 [국내 글쓰기 자료 조사](../../research/korean-sources.md)에 있다.

## 자료

| 파일 | 내용 |
|---|---|
| [`sources.json`](sources.json) | 원문 10편의 발췌, 출처, 이용 조건, 발췌 범위 |
| [`spec.json`](spec.json) | 원문마다 요청문과 판정 기준(`must_preserve`·`must_not`·`exact`) |
| [`slop.json`](slop.json) | deslop 입력. 부풀린 글, 만든 요청, 사실 검수 결과 |
| [`cases.json`](cases.json) | 위 세 파일로 만든 사례. `node scripts/eval/human.mjs build` |

원문은 대한민국 정책브리핑(www.korea.kr)의 정책기자단 기사 8편과 정책뉴스 2편이다. 2018~2022년에 게시됐고 공공누리 제1유형(출처표시)으로 공개된 글이다. 글마다 제목·글쓴이·게시일·주소를 `sources.json`에 적었다. 사진과 글쓴이의 전자우편 주소는 넣지 않았다.

### 개발용과 확인용

원문 10편을 반으로 나눴다. 스킬을 고칠 때는 개발용 5편(사례 `split: "dev"`)의 결과만 본다. 확인용 5편(`split: "test"`)은 고친 스킬을 고정한 뒤에 한 번 돌린다.

| 개발용 | 확인용 |
|---|---|
| 한강 발원지 체험기(2018), 긴급고용안정지원금 신청기(2020), 문서24 후기(2021), 베이징 올림픽 응원(2022), 국가장학금 안내(2021) | 정책기자단 모집(2020), 무착륙 관광비행 체험기(2021), 해외입국자 관리 체험기(2022), DMZ 생생누리 방문기(2022), 국민지원금 문답(2021) |

## 부풀린 글 만들기

`node scripts/eval/human.mjs slop`이 원문마다 다음을 한다.

1. 스킬이 없고 도구도 없는 새 세션(`claude-sonnet-5-5`)에게 원문과 함께 이렇게 요청한다. "아래 글을 더 전문적이고 매력적인 글로 풍성하게 다듬어 줘. 독자의 흥미를 끌 수 있게. 사실, 숫자, 날짜, 이름, 링크는 바꾸거나 새로 만들지 마. 다듬은 글만 보내 줘."
2. 판정 모델(`claude-opus-5-5`)이 원문과 결과를 대조한다([검수 지침](../judge/slop-check.md)). 수식어·형식·반복은 문제 삼지 않고, 사실이 바뀌거나 빠지거나 새로 생겼는지만 본다.
3. 통과하지 못하면 세 번까지 다시 만든다. 세 번 모두 통과하지 못한 원문은 deslop 사례를 만들지 않는다.

## 비교하는 조건

| 조건 | 내용 |
|---|---|
| A | 글빨 없음 |
| B | 글빨 0.2.1 (`evals/snapshots/v0.2.1`) |
| C1, C2 | 개선 라운드 후보(`evals/snapshots/v0.3.0-r1`, `v0.3.0-r2`). 개발용 사례에만 돌렸다 |
| C | 고정한 글빨 0.3.0(`v0.3.0-r2`와 같다). 확인용 사례에만 돌렸다 |
| H | 사람이 쓴 원문. 실행하지 않는다. polish에서는 입력과 같은 글이고, deslop에서는 부풀리기 전의 원문이다 |

작성 조건과 판정 방법은 [평가 안내](../README.md)와 같다. 여기에 H와의 품질 비교를 더했다. polish에서 H에 지면 판정 모델이 고친 글을 원래 글보다 못하다고 본 것이고, deslop에서 H와 비기거나 이기면 사람이 쓴 원래 글만큼 읽힌다고 본 것이다. 품질 판정 모델은 어느 쪽이 사람 글인지 모른다. 다만 판정 모델이 모델의 문체를 선호할 수 있으므로, 이 비교를 사람 글보다 낫다는 근거로 쓰지 않는다.

## 결과

자세한 내용은 [2차 평가 보고서](../results/REPORT-human.md)에 있다. 사례마다 원문과 결과를 보려면 [확인용](../results/cases/human-test/README.md)과 [개발용](../results/cases/human-dev/README.md) 페이지를 연다.

| | 글빨 없음 | 글빨 0.2.1 | 글빨 0.3.0 |
|---|---|---|---|
| 의미 보존, 18개 사례 × 2회(기준선) | 15/36 | 32/36 | |
| 의미 보존, 확인용 9개 × 2회 | 8/18 | 16/18 | 16/18 |
| 품질 비교, 확인용(0.3.0과) | 2 대 2 (엇갈림 3) | 3 대 2 (같음 5, 엇갈림 4) | |

- 글빨 없음의 실패 21회 중 15회는 전해 들은 말이나 추측을 단정으로 바꾸는 등 확실성이 바뀐 경우였다.
- 0.3.0은 확인용 사례에서 0.2.1과 차이를 보이지 않았다.
- 판정 모델은 사람 원문보다 고친 글을 거의 항상 골랐다(0.2.1과 비교해 사람 원문 3 대 26). 사람 원문이 이긴 경우는 모두 부풀린 글의 소제목 구성이 남은 결과와 비교했을 때였다.
- 부풀린 글을 만들 때 스킬 없는 모델은 10편 중 4편에서 첫 시도에 사실을 바꿨다. 주로 전해 들은 말을 단정으로 바꿨다.
