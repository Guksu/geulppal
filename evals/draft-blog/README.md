# 블로그 글·에세이 평가

블로그 글이나 에세이는 겪은 일을 짧게 적어 주거나, 주제와 한두 줄만 주고 써 달라고 하는 경우가 많다. 여기서는 작성 모델에게 요청과 입력만 주고 블로그 글·에세이를 처음부터 쓰게 한다. 가장 중요한 실패는 입력에 없는 경험·장면·감정을 글쓴이가 겪은 일처럼 지어내는 것이다.

## 입력 세 가지

| 입력 | 사례 수 | 내용 |
|---|---|---|
| 글쓴이 메모 | 9 | 원래 글에서 별도 세션이 뽑은 메모. 겪은 일과 순서, 본 것, 들은 말, 정보, 글쓴이가 밝힌 느낌·의견 |
| 주제와 한두 줄 | 4 | 원래 글에 있는 사실로만 적은 한두 줄. 쓸 수 있는 내용이 적다 |
| 참고 글 + 메모 | 3 | 다른 사람이 쓴 체험기 한 편을 말투 참고로 붙이고, 그 아래 메모를 준다. 참고 글의 내용은 근거가 아니다 |

## 만드는 방법

1. **원래 글**: 대한민국 정책브리핑 정책기자마당의 체험기 16편(2019~2022년 게시, 공공누리 제1유형). 본문 텍스트만 쓰고 사진·표와 글쓴이 서명·소개는 뺐다.
2. **메모**: 스킬 없는 별도 세션이 원래 글을 글쓴이가 쓰기 전에 적어 두었을 법한 메모로 되돌린다. 판정 모델이 원래 글과 대조해 빠지거나 바뀌거나 더해진 내용이 없을 때만 쓴다([`blog-memo-check.md`](../judge/blog-memo-check.md)). 12편 모두 통과했다(1편은 세 번째 시도).
3. **한두 줄 입력**: 원래 글에 있는 사실로만 직접 적었다.
4. **참고 글**: [사람이 쓴 글 평가](../human/README.md)의 체험기 3편(문서24 이용기, 긴급고용안정지원금 신청기, 무착륙 관광비행 체험기)을 썼다.
5. **기준 조건 H**: 메모로 쓰는 사례는 원래 글을 사람 글로 두고 품질을 비교한다. 한두 줄 입력 사례는 원래 글이 입력보다 훨씬 많은 내용을 담고 있어 비교하지 않는다.

```bash
node scripts/eval/memo.mjs sources --dir evals/draft-blog
node scripts/eval/memo.mjs memo --dir evals/draft-blog --ids <메모가 필요한 글>
node scripts/eval/memo.mjs build --dir evals/draft-blog
```

## 판정

- **근거 판정**([`draft-blog-claims.md`](../judge/draft-blog-claims.md)): 입력이 유일한 근거다. 겪은 일·장면(장소, 날짜, 날씨, 함께 있던 사람, 본 것, 들은 말), 느낌·의견, 사실 정보마다 입력에서 근거를 찾는다. 그럴듯한 장면 묘사나 입력에 없는 깨달음도 실패로 센다. 독자에게 건네는 인사·권유, 빈칸으로 남긴 부분은 내용으로 보지 않는다. 입력이 한두 줄일 때 빈칸을 두거나 필요한 내용을 묻는 것은 실패가 아니다.
- **품질 비교**([`draft-blog-quality.md`](../judge/draft-blog-quality.md)): 한 사람이 자기 경험을 쓴 글로 읽히는지, 거창한 도입과 교훈조 마무리가 없는지, 겪은 일이 자연스럽게 이어지는지, 입력의 구체적인 내용으로 글을 끌고 가는지 본다.
