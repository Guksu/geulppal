## 소개

Claude가 한국어로 쓴 답변, 작업 보고, PR·커밋 설명, 문서를 사람들이 평소에 쓰는 한국어로 다듬는 스킬입니다. Claude의 한국어에는 영어로 먼저 떠올린 표현을 낱말대로 옮긴 말, 작업하면서 붙인 이름, 영어 어순을 따른 문장이 섞이기 쉽습니다. 글빨은 이런 곳을 찾아 고치고, 고치면서 사실·조건·작성자의 말투는 바꾸지 않습니다.

판단 기준은 하나입니다. 영어 원문을 모르는 한국어 독자가 읽고 바로 뜻을 아는가. 아래 표의 표현은 고칠 곳을 찾는 단서이며 금지어 목록이 아닙니다.

## 무엇을 고치나

| Claude가 흔히 쓰는 한국어 | 글빨을 쓰면 |
|---|---|
| `조용히 버려집니다`, `조용히 실패합니다`처럼 영어 표현을 낱말대로 옮긴 말 | 실제로 일어나는 일로 씁니다. `오류 없이 버려집니다` |
| `진실의 원천이 둘`, `커버리지가 얇습니다`, `타입이 거짓말을 합니다` | `기준이 되는 곳이 둘`, `테스트가 적습니다`, `타입이 실제 값과 맞지 않습니다` |
| 작업하면서 붙인 이름을 설명 없이 씀(`스냅샷 게이트에서 드리프트가 잡혀서`) | 처음 한 번 무엇인지 풀어 씁니다 |
| 명사 나열(`입력값 검증 실패 처리 로직 개선`) | 동사로 풉니다(`입력값 검증에 실패했을 때의 처리를 고쳤다`) |
| 화살표·콜론으로 대신한 설명(`원인: 캐시 키 충돌 → 노출 가능성`) | 서술어가 있는 문장으로 씁니다. 표와 목록 항목은 그대로 둡니다 |
| `~을 가지고 있다`, `~에 있어서`, `~되어지다` | `~이 있다`, `~에서`, `~되다` |
| `결론부터 말하면`, `핵심은 ~입니다`가 문단마다 | 말버릇을 덜고 내용부터 씁니다 |
| `혁신적인`, `판도를 바꾸는` 같은 과장과 익숙한 비유 | 실제 동작과 결과로 씁니다 |
| key를 `열쇠`, feature를 `특징`으로 옮기는 과잉 번역 | 기술 개념의 이름은 개발자가 부르는 대로 둡니다(`키`, `피처`) |
| 다듬다가 `가능하다고 합니다`를 `가능합니다`로 바꿈 | 전해 들은 말·추측·조건·범위(`만`, `등`)를 그대로 둡니다 |

실제 결과에서 옮긴 전후 비교는 [문장 비교](comparisons.md)에 있습니다.

## 설치

한 번만 설치하면 됩니다. 평가는 Claude Code에서만 했습니다.

### Claude Code

프로젝트 폴더의 터미널에서 실행합니다. [skills CLI](https://skills.sh/docs/cli)가 스킬을 `.claude/skills/geulppal/`에 넣습니다.

```bash
npx skills add Guksu/geulppal --skill geulppal        # 이 프로젝트에서만
npx skills add Guksu/geulppal --skill geulppal -g     # 모든 프로젝트에서
```

skills CLI 없이 직접 복사해도 됩니다.

```bash
git clone --depth 1 https://github.com/Guksu/geulppal.git
mkdir -p ~/.claude/skills
cp -R geulppal/skills/geulppal ~/.claude/skills/        # 모든 프로젝트에서
# 한 프로젝트에서만 쓰려면 그 프로젝트의 .claude/skills/에 복사합니다
```

같은 이름의 스킬이 이미 있다면 먼저 내용을 비교하세요.

### Claude 웹·데스크톱

`skills/geulppal/` 폴더를 ZIP으로 묶어 업로드합니다. ZIP을 열었을 때 `geulppal/SKILL.md`가 있어야 합니다.

```bash
git clone --depth 1 https://github.com/Guksu/geulppal.git
cd geulppal/skills && zip -r geulppal.zip geulppal
```

[ZIP 업로드 안내](https://support.claude.com/en/articles/12512198-how-to-create-custom-skills)

### 다른 에이전트

skills CLI는 Claude Code 말고도 설치된 에이전트를 골라 넣을 수 있습니다(`-a <에이전트>`). 다만 다른 에이전트에서는 평가하지 않았습니다.

설치되는 것은 `skills/geulppal/`의 파일 세 개(약 38KB)뿐입니다. 평가 자료와 스크립트는 들어가지 않습니다.

## 업데이트

업데이트 전에 [변경 내역](https://github.com/Guksu/geulppal/pulls?q=is%3Apr+is%3Amerged)을 확인하세요.

- skills CLI로 설치했다면 설치한 프로젝트에서 `npx skills update geulppal`을 실행합니다. 전역 설치는 `-g`를 붙입니다.
- 직접 복사했다면 저장소를 다시 받아 `skills/geulppal/` 폴더를 통째로 바꿉니다.
- Claude 웹·데스크톱은 새로 묶은 ZIP을 다시 업로드합니다.

## 동작 방식

1. 글빨은 스킬 하나입니다. 설치하면 Claude는 시작할 때 글빨의 설명문만 읽어 둡니다.
2. 한국어 글을 다듬어 달라는 요청이면 Claude가 글빨을 엽니다. 직접 부르려면 `/geulppal`을 앞에 붙입니다.
3. Claude는 `SKILL.md`를 읽고 이 순서로 고칩니다.
   - 문장이 실제로 말하려는 일(무엇이 어떻게 되는가)을 정합니다.
   - 그 일을 독자가 평소에 쓰는 말로 씁니다. 기술 개념의 이름은 옮기지 않습니다.
   - 영어 원문을 떠올려야만 뜻이 통하는 말이 남았는지 다시 읽습니다.
   - 고친 글이 원래 글과 같은 사실·조건·확실성을 전하는지 대조합니다.
4. 원문 없이 새로 써 달라는 요청(README, 보고서, 블로그 등)이면 [`references/document-types.md`](../skills/geulppal/references/document-types.md)의 내용 규칙도 읽습니다. 자료에 없는 사실은 보태지 않습니다.
5. 붙여 넣을 글을 요청하면 완성문만 돌려줍니다. 원문에 없어 비워 둔 사실처럼 확인할 것이 있을 때만 완성문 뒤에 짧게 적습니다.

| 요청 | 글빨이 하는 일 |
|---|---|
| "방금 쓴 답을 자연스러운 한국어로 다듬어 줘" | 낱말대로 옮긴 말, 설명 없는 이름, 어색한 문장을 고친 완성문 |
| "이 PR 설명 영어 직역 같아. 읽기 좋게 고쳐줘" | 같은 사실과 테스트 범위를 유지한 채 문장만 다듬음 |
| "이 문장 번역투 고쳐줘" | `~에 있어서`, `~을 가지고 있다` 같은 표현을 같은 뜻으로 바꿈 |
| "AI 티 빼줘" | 과장, 반복, 형식적인 도입·결론, 대화용 안내를 덜어냄 |
| "이 저장소 README를 한국어로 써 줘" | 코드에서 확인한 사실만으로 초안을 씀 |

0.5 설명으로 잰 자동 선택에서는 한국어 글을 다듬어 달라는 요청 18번을 모두 골랐고, 버그 수정·개발 질문·AI 작성 판별 같은 요청 16번은 한 번도 고르지 않았습니다. 영어 문서를 다듬어 달라는 요청 2번은 고르지 않았으므로 영어 글은 `/geulppal`로 직접 부르세요. [자동 선택 결과](../evals/results/2026-11-03-trigger/trigger-v0.5.2.md)

> **스킬**은 AI 에이전트가 필요할 때 읽는 설명서입니다. 글빨은 평소에는 설명문만 차지하고, 글을 다듬을 때만 본문과 참고 문서를 읽습니다.

## 하지 않는 일

- AI가 쓴 글인지 판별하지 않습니다. 탐지기 통과율을 보장하지 않습니다.
- 특정 단어나 문장부호를 기계적으로 지우지 않습니다. 업계에서 굳은 용어(캐시, 렌더링, 롤백)는 바꾸지 않습니다.
- 코드 블록, 명령어, 경로, 설정 키, 인용문은 문장을 다듬는다는 이유로 바꾸지 않습니다.
- 이미 자연스럽고 정확한 문장은 그대로 둡니다. 글자 수를 줄이는 것이 목표가 아닙니다.
- 처음부터 쓰게 할 때의 효과는 사례에 따라 엇갈렸습니다. 다 쓴 글을 다듬게 하는 쪽을 권합니다.

## 평가

같은 요청·모델·설정에서 글빨이 있을 때와 없을 때를 비교했습니다. 스킬을 고정한 뒤 처음 보는 사례로 확인했습니다.

- **한국어 표현(0.5):** 처음 보는 사례 12개에서 글빨 없이 쓴 답을 다듬게 했습니다. 표시된 표현 48개 중 글빨 없이 다듬으면 18개, 0.5.2로 다듬으면 8개가 남았습니다. 뜻을 지킨 결과는 글빨 없음 22/24, 0.5.2 23/24였습니다.
- **판정 기준 확인:** 판정 모델의 표시를 저장소 소유자가 문장 10개로 확인했을 때 7개가 일치했습니다.
- **뜻 보존(0.4까지):** 사람이 쓴 README 16개를 다듬을 때 사실·조건을 지킨 결과는 글빨 없음 20/32, 글빨 31/32였습니다.

방법과 전체 결과는 [문장 비교](comparisons.md), [벤치마크](../evals/results/README.md), [평가 방법](../evals/README.md)에 있습니다.

## 구성

```text
skills/geulppal/                    설치되는 스킬
├─ SKILL.md                         한국어 독자가 멈칫하는 곳 · 이름은 옮기지 않기 · 번역투 · 과장과 반복 · 뜻 지키기 · 출력 방식
└─ references/
   ├─ document-types.md             원문 없이 새로 쓸 때의 내용 규칙 · README·PR·기획서·블로그·이메일 기준
   └─ editing-examples.md           고칠 문장과 그대로 둘 문장
```

## 저장소 구조

```text
geulppal/
├─ skills/geulppal/                 설치되는 스킬
├─ docs/                            상세 안내 · 문장 비교
├─ evals/                           평가 사례 · 판정 지침 · 결과 · 평가한 스킬 사본(snapshots/)
├─ scripts/eval/                    실행 · 판정 · 집계 · 구조 검사 스크립트
├─ research/                        설계 근거(국내 글쓰기 자료, 오웰의 원칙 검토 등)
└─ AGENTS.md                        이 저장소에서 작업할 때의 규칙
```

## 개발

| 명령어 | 확인 항목 |
|---|---|
| `node scripts/eval/check.mjs` | 구조 검사: 평가 사례 형식, 스킬 설명 길이, 문서 링크, 평가한 스킬 사본의 해시, 공개 결과의 로컬 경로 노출. 모델을 부르지 않습니다 |
| `node scripts/eval/run.mjs` | `claude -p`로 사례 실행(조건마다 격리된 설정) |
| `node scripts/eval/judge.mjs` | 판정 모델로 뜻 보존, 멈칫할 곳, 품질 비교 |

실행과 판정은 실제 모델을 부르므로 사용량이 듭니다. 명령 전체와 다시 돌리는 방법은 [평가 방법](../evals/README.md)에 있습니다.

## 기여하기

가장 도움이 되는 기여는 실제로 어색하게 남은 문장입니다. [이슈](https://github.com/Guksu/geulppal/issues)에 원문, 요청, 결과를 함께 적어 주세요. 평가 사례로 옮겨 다음 버전을 확인하는 데 씁니다.

스킬을 고칠 때는 이 순서를 따릅니다.

1. 고치기 전에 처음 보는 평가 사례를 먼저 추가하고 커밋합니다.
2. 스킬을 고친 뒤 `evals/snapshots/`에 사본을 두고 해시를 기록합니다.
3. 글빨 없음과 이전 버전을 같은 CLI 버전으로 함께 실행해 비교합니다.
4. 구조 검사와 실제 모델 실행을 구분해 보고합니다. 실행하지 않은 평가를 통과했다고 쓰지 않습니다.

코딩 에이전트로 작업한다면 [`AGENTS.md`](../AGENTS.md)가 공통 규칙입니다.
